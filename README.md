## Сборка и запуск

Сборка проверена на Rust 1.97.1, edition 2024. Для фиксированных буферов используется `arrayvec 0.7.8`. Собственный `unsafe` разрешён только внутри private NNUE SIMD kernels; остальные модули используют безопасный Rust. Лицензия — GPL-3.0-or-later: позиционные таблицы адаптированы из Stockfish 15, см. [авторство и зависимости](THIRD_PARTY.md) и [полный текст лицензии](LICENSE).

```powershell
cargo build --release
.\target\release\zenith.exe
```

На Linux/macOS исполняемый файл — `./target/release/zenith`. Для подключения к шахматному GUI выберите этот файл как UCI-движок.

После запуска можно вводить команды по очереди:

```text
uci
isready
position startpos moves e2e4 e7e5
go depth 6
```

Дождитесь строки `bestmove`. Команда `stop` прерывает расчёт и возвращает лучший ход последней завершённой итерации; `quit` завершает процесс. Закрытие stdin тоже останавливает движок, поэтому конвейер, который сразу закрывается после `go`, не подходит для замера поиска.

## Что реализовано

- 12 битбордов, таблицы атак пешек/коней/королей и генерация всех легальных ходов.
- Предвычисленные лучи слонов/ладей с поиском ближайшего блокера битовыми операциями. В quiescence отдельно генерируются легальные взятия и все превращения; в шахе сохраняются все уходы, пат проверяется до stand-pat.
- Рокировки, взятие на проходе с проверкой вскрытого шаха, четыре превращения, FEN и UCI-нотация ходов.
- Детерминированный инкрементальный Zobrist-хеш; поле en passant учитывается только при наличии легального взятия. Тесты сравнивают ключи после ходов с полным восстановлением из FEN.
- Lazy SMP: `Threads=1..64`, общая согласованная TT, отдельные истории и оценочные кэши, общий лимит узлов и времени.
- Syzygy до 7 фигур: DTZ-ход в корне, WDL-отсечения после обнуления счётчика, `tbhits`, безопасный возврат к поиску при отсутствии таблицы.
- Итеративное углубление, alpha-beta/PVS, aspiration windows, quiescence, упорядочивание ходов и ограниченная по памяти таблица транспозиций.
- Осторожный LMR для поздних тихих ходов вне PV: улучшившие оценку ходы пересчитываются на полной глубине. Шахи, взятия, превращения, пешечные ходы, killers и матовые окна не сокращаются.
- Null move pruning вне PV с повторной проверкой реальными ходами. Исключены шах, корень, малые глубины, матовые окна, близость правила 50 ходов и позиции с малым материалом.
- SEE по легальным наименее ценным атакующим: связки, безопасные взятия королём, вскрытые линии, en passant и превращения. Поэтапный MovePicker: TT-ход, неотрицательные размены, тихие ходы по killers/history, проигрышные размены. В quiescence SEE также используется для осторожного отсечения проигрышных взятий.
- Классическая оценка с позиционными таблицами, плавным переходом стадий, мобильностью, давлением на короля, пешечным щитом, форпостами и оценкой проходных с учётом блокады и королей.
- Reverse futility на малой глубине вне PV, SEE/delta pruning в quiescence с сохранением шахов, превращений и опасных пешечных ходов.
- Отдельный кэш статической оценки с полным ключом; оценки повторений и 50 ходов в него не попадают.
- Учёт повторений, правила 50 ходов, недостаточного материала, мата и пата.
- Отдельный поток поиска, контроль времени/узлов и отзывчивый UCI. При игре по часам мягкий лимит зависит от устойчивости лучшего хода и падения оценки; жёсткий ограничивает расчёт внутри итерации.

Поддерживаются `uci`, `isready`, `ucinewgame`, `position startpos`, `position fen`, `setoption`, `go`, `stop`, `quit`. У `position` можно передать `moves`. У `go` поддерживаются `depth` (1–120), `nodes`, `movetime`, `wtime`, `btime`, `winc`, `binc`, `movestogo`, `searchmoves`, `infinite`. Время задаётся в миллисекундах. Несколько ограничений завершают поиск при достижении первого из них; `infinite` отключает лимит времени и удерживает `bestmove` до `stop`. Без ограничений `go` запускает бесконечный поиск.

Настройки: `Threads` (1–64, по умолчанию 8), `SyzygyPath` (каталоги таблиц), `SyzygyProbeLimit` (0–7, по умолчанию 7; 0 отключает), `SyzygyProbeDepth` (1–120, по умолчанию 1), `Hash` (1–1024 MiB, по умолчанию 16), `Clear Hash`, `Move Overhead` (0–5000 мс, по умолчанию 10), `Null Move Pruning`, `Selective Pruning`, `Search Enhancements` и `Modern Search` (все check, по умолчанию true). Настройки поиска сохраняются при смене Hash и `ucinewgame`. Дополнительная команда `d` печатает текущий FEN. `go ponder` и `go mate` пока не поддерживаются; движок сообщает об этом через `info string`.

Парсер FEN требует все шесть полей и отвергает структурно некорректные позиции. Начальная история повторений известна только из переданных ходов после `position`; один FEN не содержит историю партии. Требование ничьей при трёх повторениях или 50 ходах в поиске оценивается как ничья. Распознавание недостаточного материала консервативное, без полного решателя мёртвых позиций.

## Проверки

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo test --release --test perft -- --ignored
cargo run --release -- perft 5
```

Последняя команда выводит разбиение дерева по первым ходам, число узлов, время и скорость. Для начальной позиции глубина 5 должна дать **4 865 609** узлов. Своя позиция:

```powershell
.\target\release\zenith.exe perft 4 "r3k2r/p1ppqpb1/bn2pnp1/3PN3/1p2P3/2N2Q1p/PPPBBPPP/R3K2R w KQkq - 0 1"
```

Здесь ожидается **4 085 603** узла. Perft проверяет правила и генерацию ходов; его скорость и успешное прохождение не измеряют силу игры.

Эталонные позиции сверены с [Perft Results](https://www.chessprogramming.org/Perft_Results) и [тестами Stockfish](https://github.com/official-stockfish/Stockfish/blob/master/tests/perft.sh). Процессные тесты проверяют взаимодействие через stdin/stdout, остановку, лимиты и завершение процесса. Протокол: [спецификация UCI, апрель 2006](https://backscattering.de/chess/uci/).

- `src/eval.rs` — статическая оценка.

- `examples/nnue.rs`, `tools/nnue_reference.cjs` — стенд NNUE и независимый экспортёр/проверка арифметики.
- `src/search.rs` — поиск, таблица транспозиций и ограничения.
- `src/search/tt.rs` — кластерная таблица транспозиций.
- `src/openings.rs`, `data/openings.txt` — тестовые дебюты и их проверка.
- `src/dataset.rs`, `examples/collect_dataset.rs` — подготовка тихих позиций с раздельной валидацией.
- `src/uci.rs` — протокол, история партии и распределение времени.
- `src/main.rs` — запуск UCI и консольного perft.
- `src/bench.rs` — фиксированный набор для замера поиска.
- `examples/match.rs` — короткие парные матчи двух UCI-движков с проверкой легальности ходов.
- `tests/` — независимые эталонные позиции и тесты реального процесса.

Позиции копируются при ходе. Атаки скользящих фигур используют таблицы лучей размером 4 KiB и ближайшего блокера; магических битбордов пока нет. Проверка сравнивает результат с простым пошаговым эталоном для каждого подмножества блокеров на каждой клетке, включая заполнение всех клеток вне лучей. Тактический генератор сравнивается с отфильтрованным полным генератором в деревьях эталонных позиций.

## Следующие этапы

1. Зафиксировать контрольные матчи: одинаковые контроль времени, оборудование, дебютные позиции и смена цветов; считать результат и доверительный интервал. Отдельно выбрать рейтинговую шкалу для цели 3000 Elo.
2. Профилировать генератор, хеширование и поиск; измерить эффект инкрементального состояния, более быстрых атак и уменьшения аллокаций.
3. Настраивать LMR и null move, затем исследовать другие отсечения с отдельными проверками цугцванга и тактических ошибок.
4. Выполнить полноценное обучение NNUE v1 через готовый потоковый binpack reader или Parquet-пайплайн; затем проверить игровые сети и подключить аккумуляторы к поиску.
5. Настраивать масштабирование Lazy SMP и расширять эндшпильные проверки; затем дополнительные возможности UCI.

Сейчас нет обученных NNUE-весов или NNUE в игровом поиске, игровой дебютной книги, Chess960 или измеренного Elo. Каждый прирост силы должен подтверждаться матчами, отдельно от роста скорости.

## Сравнение поиска и версий

```powershell
cargo run --release -- bench 6 --no-lmr
cargo run --release -- bench 6
cargo run --release -- bench 6 --no-see
cargo run --release -- bench 7 --no-nmp
cargo run --release -- bench 7 --nmp
cargo run --release --example match -- .\target\release\zenith.exe .\target\baselines\zenith-0.1.0.exe 4 5000
```

`bench` очищает 16 MiB hash и эвристики перед каждой из пяти позиций, печатает глубину, оценку, ход, узлы и время. `--no-lmr` позволяет сравнить алгоритмы в одной сборке. Сокращение дерева не доказывает рост Elo; повторяйте замеры на свободном компьютере.

В 0.3.0 флаг `--no-see` включает прежнее упорядочивание MVV-LVA/killers/history для сравнения с SEE/MovePicker. Флаги можно объединять: `bench 6 --no-lmr --no-see`. С выключенным LMR тесты сравнивают оценки обоих вариантов полного поиска. Сам список легальных ходов пока генерируется заранее; поэтапными являются выдача и оценка, а вычисление SEE откладывается до завершения проверки TT-хода. Все четыре превращения и тихие уходы от шаха сохраняются.

SEE использует последовательность легальных LVA-взятий с возможностью остановить размен; это эвристика материального обмена на одной клетке. Она не решает все тактические угрозы и не перебирает все альтернативные порядки взятий. Тестовый эталон строит такую же LVA-последовательность через полный генератор легальных ходов независимо от битбордового поиска атакующих и свёртки размена. Одинаковые баллы сохраняют исходный порядок ходов. Для дорогих взятий есть быстрый неотрицательный тест, отключённый на последней/первой горизонтали из-за возможных превращений при ответном взятии.

Проверка 0.3.0: 64 обычных теста проходят в release, Clippy и форматирование чистые. В трёх последовательных парах `bench 6 --no-see` / `bench 6` число узлов составило 1 176 922 / 972 600 (−17.4%); оценки и лучшие ходы на пяти позициях совпали. Времена без SEE: 3.697254 / 3.683224 / 3.677564 с; с SEE: 3.482269 / 3.406473 / 3.471003 с. Медианное время уменьшилось примерно на 5.8% на этой машине. По числу узлов в секунду вариант с SEE медленнее: выигрыш в общем времени получен за счёт меньшего дерева, и на других позициях он не гарантирован.

Короткий парный матч против сохранённой сборки до SEE: 5 побед, 1 ничья, 2 поражения при 5000 узлов на ход, четыре дебюта со сменой цветов, без нелегальных ходов и зависаний. Этого недостаточно для вывода о приросте Elo. Локальные логи: `target/bench-legacy-ordering.txt`, `target/bench-see-ordering.txt`, `target/match-see-final.txt`; baseline — `target/baselines/zenith-before-see.exe`. Семантика SEE и порядок стадий сверены с [Static Exchange Evaluation](https://www.chessprogramming.org/Static_Exchange_Evaluation) и [Move Ordering](https://www.chessprogramming.org/Move_Ordering).

## Проверки 0.4.0

Поиск по умолчанию сохраняет дерево 0.3.0: на пяти позициях `bench 6` совпали все лучшие ходы, оценки и число узлов по каждой позиции, суммарно 972 600 узлов. Три последовательные пары release-прогонов при 16 MiB hash: 0.3.0 — 4.986847 / 5.473855 / 4.968015 с; 0.4.0 — 2.338188 / 2.245189 / 2.679564 с. Медианы 4.986847 и 2.338188 с: на этом наборе время сократилось примерно на 53%, скорость выросла примерно в 2.1 раза. Это измерение стоимости прежнего дерева на одной машине, без оценки прироста Elo.

69 обычных тестов и отдельный глубокий perft-набор проходят; Clippy и форматирование чистые. Скользящие атаки проверены против пошагового эталона для всех вариантов блокеров. Тактический генератор сохраняет порядок прежнего отфильтрованного списка, en passant и все превращения. В шахе по-прежнему исследуются тихие спасения; пат определяется до stand-pat.

Эксперимент с историей включает bounded gravity для положительных/отрицательных бонусов, штрафы только уже проверенным альтернативам и capture history по стороне, атакующей фигуре, клетке и жертве. Значения стареют между поисками, сбрасываются при `clear` и переключении режима. Основа: [History Heuristic, включая Capture History](https://www.chessprogramming.org/History_Heuristic). Его можно включить через `bench 6 --history` или `Search::set_advanced_history(true)`; обычный UCI использует прежний режим. `--no-history` явно возвращает прежнюю историю; этот флаг можно комбинировать с `--no-lmr` и `--no-see`.

До оптимизации атак/генерации кандидат с расширенной историей сыграл против 0.3.0: +6 =2 −8 при 10 000 узлов на ход. Четыре дебюта со сменой цветов повторялись дважды, поэтому 16 партий не являются 16 независимыми наблюдениями. Бенчмарк сократился лишь с 972 600 до 969 540 узлов. Преимущество не подтверждено, и история оставлена выключенной. [PGN этого эксперимента](games/zenith-history-experiment.pgn) сохранён отдельно; он не представляет поведение выпуска 0.4.0 по умолчанию.

## Null move pruning в 0.5.0

Выключен по умолчанию. Включение: `bench 7 --nmp`, `Search::set_null_pruning(true)` или UCI-команда `setoption name Null Move Pruning value true`. Флаг `--no-nmp` явно отключает его. Переключение очищает TT и историю. Бенчмарк печатает `null_probes` и `null_cutoffs`, чтобы было видно, применялось ли отсечение.

Условия: не корень, окно в один centipawn вне матового диапазона, глубина не менее 4, нет шаха, счётчик обратимых полуходов меньше 80. У стороны должны оставаться пешка и минимум две другие фигуры общей стоимостью не менее 950; статическая оценка должна превышать beta хотя бы на 50. После пропуска хода исследуется глубина `max(1, depth − 3 − depth/6)`, после успешной пробы — реальные ходы исходной позиции на `max(1, depth − 3)`. Отсечение возвращает границу beta, без искусственной матовой оценки.

В пробе и проверочном поддереве отключены повторный NMP, LMR, чтение поисковых оценок TT, запись TT и обучение history/killers. TT-ход по-прежнему может упорядочивать легальные ходы. Пропуск сбрасывает en passant, но не меняет реальные счётчики партии. Повторения до искусственной границы исключены. Выход по лимиту восстанавливает путь и режим поиска как при пробе, так и при проверке. Мат/пат определяются до NMP. Проверка на сокращённой глубине снижает риск цугцванга, но не доказывает безопасность любого отсечения.

Основа сверена с [Null Move Pruning](https://www.chessprogramming.org/Null_Move_Pruning) и блоком NMP в [зафиксированном поиске Reckless](https://github.com/codedeliveryservice/Reckless/blob/69aea9086899189ee38fd3e556bf9469b805552a/src/search.rs#L566). Реализация адаптирована к копируемой позиции и строгому контексту повторений Zenith; коэффициенты Reckless не переносились.

На `bench 6` число узлов уменьшилось с 972 600 до 968 028 (−0.47%); ходы и оценки совпали. Три пары времён без/с NMP: 1.812652 / 1.978916 с, 1.744169 / 1.876777 с, 1.672135 / 1.703497 с. Медиана с NMP здесь хуже на 7.6%: на малой глубине стоимость проб не окупается. Эффект зависит от глубины и позиции.

Это измерение на пяти позициях одной машины, без вывода о силе игры.

## Пакет усиления 0.6.0

Выбраны изменения, закрывающие пробелы классического ядра до NNUE:

- **Оценка.** Вместо формул центра/продвижения — таблицы миттельшпиля и эндшпиля из [Stockfish 15](https://github.com/official-stockfish/Stockfish/blob/sf_15/src/psqt.cpp), масштабированные вдвое, с прежними материальными ценностями Zenith. Полная оценка Stockfish и его сеть не переносились; авторство и GPL сохранены в [THIRD_PARTY.md](THIRD_PARTY.md).
- **Активность.** Мобильность вне своих фигур и атак неприятельских пешек, поддержанные форпосты, ладьи на седьмой горизонтали. Координация атак на кольцо короля оценивается нелинейно, слабее без ферзя. Пешечный щит учитывает два ряда и открытые/полуоткрытые линии. Геометрические атаки учитывают блокеров, но не решают связки; это эвристика оценки, не генератор легальных ходов.
- **Проходные и окончания.** Блокада уменьшает бонус проходной, учитываются расстояния обоих королей до следующей клетки. Задняя сдвоенная пешка больше не получает бонус проходной. Против одинокого короля при наличии ладьи/ферзя поощряются приближение своего короля и вытеснение чужого к краю.
- **Quiescence.** Взятие пропускается при SEE ниже −80 либо если stand-pat + цена жертвы + 180 не перекрывает alpha. Исключены уходы от шаха, шахующие ходы, превращения, продвижения пешек на шестую/седьмую горизонтали, позиции с шестью или меньшим числом фигур, матовые границы и близость правила 50 ходов. Мат/пат определяются до stand-pat.
- **Reverse futility.** Статическое отсечение на глубинах 1–3 вне корня/PV, запас `120 × depth + 70`. Нужны пешка и две фигуры помимо короля общей стоимостью от 950; исключены шах, матовые границы и близость правила 50 ходов. В проверочных NMP-поддеревьях новые отсечения отключены. Это эвристики, не доказательство безопасности каждого отсечения.
- **Кэш оценки.** Отдельная таблица с полным ключом хранит только статический score, без результатов повторений и правила 50 ходов. Сторона хода входит в ключ. Кэш выделяется из бюджета Hash, максимум 1 MiB. TT сохраняет прежние требования к истории и счётчику полуходов.
- **Время.** Мягкий бюджет использует остаток/число ходов и 3/4 инкремента. Жёсткий — до четырёх мягких бюджетов, не более половины доступного остатка после overhead. Мягкая остановка происходит после завершённой итерации от глубины 3: устойчивый ход уменьшает бюджет, смена хода или падение оценки увеличивают. Единственный разрешённый корневой ход уменьшает бюджет. Явный `movetime` сохраняет самостоятельный жёсткий лимит; `infinite` отключает оба.

Источники: [Quiescence Search](https://www.chessprogramming.org/Quiescence_Search), [Reverse Futility Pruning](https://www.chessprogramming.org/Reverse_Futility_Pruning), [King Safety](https://www.chessprogramming.org/King_Safety), [Time Management](https://www.chessprogramming.org/Time_Management) и ранее зафиксированный поиск Reckless. Коэффициенты Reckless не копировались.

Отсечения включены по умолчанию. Отключение: `bench 6 --no-pruning`, `Search::set_pruning(false)` или `setoption name Selective Pruning value false`. NMP и расширенная история остаются выключенными. Бенчмарк дополнительно выводит qnodes, отсечения quiescence/RFP и попадания кэша оценки. Флаги сочетаются с `--no-lmr`, `--no-see` и `--nmp`.

Фиксированное время проверяет совокупную стоимость оценки/поиска, но не измеряет пользу нового распределения времени по общим часам.

## Поиск и испытания 0.7.0

Пакет внедрён целиком, с общим переключателем `Search Enhancements`. В API — `set_enhancements(false)`, в бенчмарке — `--no-enhancements`. Переключатель отключает continuation/countermove, адаптивную формулу LMR и продления; кластерная TT остаётся. Настройки 0.6.0 для NMP и прежнего capture/malus history сохранены.

- **Continuation history:** контексты предыдущего полухода и предыдущего хода той же стороны, индексы типа фигуры и клетки назначения. Ограниченные gravity-бонусы получает тихий ход отсечения; штрафуются только уже проверенные тихие альтернативы. Таблицы хранятся в heap, занимают суммарно около 1.125 MiB вне Hash, стареют раз в 16 поисков и очищаются вместе с новой партией/Hash. Переход через искусственный null move не обучает эту историю.
- **Countermoves:** удачный тихий ответ на предыдущий ход сортируется после killers, перед обычной историей. Устаревшая запись лишь меняет порядок уже легальных ходов.
- **Адаптивный LMR:** заранее вычисленная таблица зависит от логарифмов глубины и номера хода. Учитываются continuation/history и улучшение статической оценки относительно двух полуходов назад. Предел сокращения — один полуход до глубины 6, два от 6, три от 9, также учитывается остаток глубины. Сохраняются исключения шахов, взятий, превращений, пешек, killers и countermoves; улучшивший alpha результат пересчитывается на полной глубине.
- **Продления:** шах с максимум тремя ответами или единственный легальный ход добавляет один полуход, максимум два продления на весь путь. Бюджет передаётся по значению детям и не сбрасывается при PVS-пересчёте. В NMP-пробе/верификации продления выключены. Входящий остаток бюджета входит в контекст TT; глубина записи — запрошенная, до локального продления.
- **TT:** четыре записи по 32 байта в корзине. Проверяются полный ключ, история, счётчик 50 ходов и бюджет продлений. Разные контексты могут сосуществовать; hash-ход переиспользуется для порядка независимо от контекста. Замещение учитывает глубину, точную границу и возраст с обёрткой поколения. Бенчмарк показывает обращения, совпадения ключа/контекста, отсечения, коллизии, замещения, продления и пересчёты LMR.

Основа: [Continuation/Countermove History](https://www.chessprogramming.org/History_Heuristic), [LMR](https://www.chessprogramming.org/Late_Move_Reductions), [Check Extensions](https://www.chessprogramming.org/Check_Extensions), [TT](https://www.chessprogramming.org/Transposition_Table). Реализация собственная; прирост Elo из этих источников не переносится на Zenith автоматически.

Дебютный набор содержит **128 уникальных легальных позиций, 32 семейства по четыре варианта**, первые восемь полуходов фиксированы. Варианты перебираются по семействам: первые 32 пары покрывают все семейства. Генератор разрешает развитие без отходов назад, ограничивает небезопасные пешечные продвижения и использует фильтры статической оценки ±120 и поиска на два полухода ±130. Фильтрующий поиск отключает новые эвристики, LMR и pruning. Это воспроизводимый инженерный набор, не профессиональная турнирная книга.

```powershell

cargo run --release --example match -- .\target\release\zenith.exe .\target\baselines\zenith-0.6.0.exe 32 10000
cargo run --release --example match -- .\target\release\zenith.exe .\target\baselines\zenith-0.6.0.exe 16 50 movetime data\openings.txt 16
```

`match` принимает необязательный путь к книге и смещение номера начала. Лог и PGN сохраняют семейство, ключ позиции и длину фиксированного начала. Экспортёр поддерживает и старые логи с шестью дебютными полуходами. Проверки дополнены коллизиями/контекстами TT, старением поколения, continuation/countermove, общим бюджетом продлений, семью точными матами в два хода и недопревращением вместо пата. ## Поиск и SIMD 0.9.0

MovePicker теперь сам генерирует псевдолегальные ходы по стадиям. Легальность проверяется у выбранного хода, и готовая дочерняя Board сразу идёт в поиск. Hash cutoff не требует генерации остальных ходов. Move lists и scored buffer используют inline `ArrayVec` с вместимостью 512, без heap и без очистки неиспользованных элементов; PV хранится в фиксированных массивах на время поиска. Предварительное продление единственного тихого хода снято, шаховые продления сохранены.

`Modern Search` включает LMP, quiet futility, history/quiet SEE pruning, IIR, pawn correction history и более широкий LMR с обычными пешечными и поздними PV-ходами. NMP теперь включён по умолчанию: modern-проба сохраняет селективность, но изолирована от TT scores и обучения; обязательная верификация сохранена на depth>=10. Защита от шахов, матовых окон, опасных пешечных ходов, маломатериальных позиций и ошибок терминальной оценки покрыта регрессиями. Это эвристики, их силу проверяем партиями.

Медианы трёх последовательных `bench 6` без параллельной компиляции/матчей: 0.8.0 — **0.787424 s**, новое ядро без modern/NMP — **0.549399 s**, полный пакет — **0.266595 s**. Узлы: 364220 / 364409 / 128490. В этом наборе время ядра уменьшилось примерно на 30%, полного пакета — на 66%; число узлов и дерево поиска меняются, это не эквивалент прироста Elo. Вариант с заранее обнулёнными большими массивами показал регрессию и заменён на ArrayVec до окончательной сборки.

NNUE использует два i16-аккумулятора (1024 байта сумм вместе), runtime AVX2 для обновления и выходного слоя, scalar fallback и отдельный dense reference. Формат весов v1 сохранён. На синтетическом стенде медиана delta+head — **0.576 мкс scalar против 0.190 мкс AVX2**, около 3.03 раза. Нейросеть пока не обучена и не подключена к игровому поиску.

113 обычных release-тестов и отдельный глубокий perft проходят. Scalar/AVX2 проверены по каждому lane, дополнительные 10000 позиций независимо пересчитаны на Node.js. Подробности, матчи и границы применимости: [отчёт 0.9.0](docs/search-simd-0.9.md).

```powershell
cargo run --release -- bench 6
cargo run --release -- bench 6 --classic
cargo run --release --example nnue -- bench target/nnue-stage1-synthetic.znnue 1000000 --scalar
cargo run --release --example nnue -- bench target/nnue-stage1-synthetic.znnue 1000000 --avx2
```

Контрольный режим UCI — `Modern Search=false` и `Null Move Pruning=false`. Lazy SMP, Syzygy, ponder, Chess960, singular extensions, PEXT и AVX-512 в этот пакет не входят.

## NNUE 0.8.0: первый этап готов

Реализована собственная компактная сеть `768 → 256 × 2 → 1`: общий feature transformer, две цветовые перспективы и CReLU. Аккумуляторы обновляются только для изменившихся piece-square признаков; работают взятия, обе рокировки, en passant, все превращения, null move, undo и смена FEN. Суммы не клипуются до выходного слоя. Сеть неизменяемая, аккумулятор привязан к её времени жизни. Рабочий поиск пока использует классическую оценку.

Есть скалярный полный reference, инкрементальный inference, квантование float-параметров и little-endian формат весов **394 820 байт** с версией, архитектурой, масштабами, checksum и проверкой числовых границ. Загрузчик ограничивает объём чтения. Обученных весов и PyTorch-тренера пока нет; синтетические веса стенда проверяют вычисления, а не силу игры.

Все **107 обычных release-тестов** проходят; один глубокий perft остаётся отдельным ignored-тестом. Проверка NNUE включает 22 фиксированных эталона независимого экспортёра/расчёта Node, специальные ходы и тысячи переходов/возвратов с проверкой каждого элемента аккумуляторов. Дополнительно Node подтвердил raw/cp на 10 000 позиций воспроизводимого прохода. В контрольном `bench 6` относительно финального `zenith-0.7.0-tuned.exe` совпадают оценки, лучшие ходы, все счётчики поиска и 364 220 узлов.

```powershell
node tools/nnue_reference.cjs fixture target/synthetic-v1.znnue
cargo run --release --example nnue -- inspect target/synthetic-v1.znnue
cargo run --release --example nnue -- walk target/synthetic-v1.znnue 10000 | Set-Content -Encoding utf8 target/nnue-walk.tsv
node tools/nnue_reference.cjs verify target/synthetic-v1.znnue target/nnue-walk.tsv
cargo run --release --example nnue -- bench target/synthetic-v1.znnue 100000
```

Для обучения выбран [датасет Mateusz Grzyb](https://huggingface.co/datasets/mateuszgrzyb/lichess-stockfish-normalized): по карточке 316 072 343 позиции с метками Stockfish, десять Parquet частей, CC BY 4.0. Полный набор не скачивался. Проверены карточка, revision и схема viewer. Нужны строгая фильтрация стандартных позиций, учёт глубины, отдельная обработка матовых меток и проверка знака cp. Название normalized не означает оценки [0,1]. Адаптер NNUE уже принимает четырёхпольный FEN, не ослабляя основной FEN-парсер.

[Спецификация архитектуры, формата, квантования и контракт будущего импорта](docs/nnue-v1.md). Следующий этап — потоковый импорт и обучение, затем подключение обученной сети к поиску и матчи. Прирост Elo до этого не заявляется.

## Подготовка NNUE: исходный сборщик outcome-данных

Сборщик читает полные UCI-логи стенда и проверяет каждый ход, результат, длину и ключ дебютной позиции. После `max(16, opening_plies + 8)` берётся каждая четвёртая позиция без шаха и доступных взятий/превращений. Терминальные позиции, недостаточный материал и близость правила 50 ходов исключаются. Партии с присуждением по лимиту полуходов не используются.

Метка — средний результат партии за белых, **не оценка Stockfish в centipawn**. Для повторяющейся позиции сохраняется число наблюдений. Семейство целиком относится к обучению или валидации по фиксированному FNV1a-хешу; одинаковая позиция, встретившаяся в обеих частях, удаляется из обеих. Позиции сортируются по полному ключу. Манифест сохраняет версию формата, фильтры, размеры частей, исходные логи и их контрольные FNV-хеши.

```powershell
cargo run --release --example collect_dataset -- target\nnue-starter target\match-0.7-vs-0.6-book-v1-10k.txt
```

Результат: `*-train.csv`, `*-validation.csv`, `*-manifest.txt`. Это проверяемый старт конвейера, а не готовая обучающая база нужного масштаба или обученная сеть. Следующие части NNUE: выбрать признаки/архитектуру, собрать намного больше партий/позиций, добавить учительские оценки, обучить и проверить квантованный inference с инкрементальными аккумуляторами на отложенных данных и в матчах.

Готовый пример из трёх финальных матчей (160 партий, одна партия по лимиту исключена): [859 обучающих позиций](data/nnue-starter-train.csv), [233 валидационные позиции](data/nnue-starter-validation.csv), [манифест](data/nnue-starter-manifest.txt). Все позиции независимо проверены в chess.js; общих канонических позиций между частями нет. Повторение:

```powershell
cargo run --release --example collect_dataset -- data\nnue-starter games\zenith-0.7.0-enhancements-vs-0.6.0-10k.uci games\zenith-0.7.0-tt-vs-0.6.0-10k.uci games\zenith-0.7.0-enhancements-vs-0.6.0-50ms.uci
```

## Партии для просмотра

В [games/zenith-0.3.0-vs-0.2.0.pgn](games/zenith-0.3.0-vs-0.2.0.pgn) сохранены все восемь партий матча в SAN. Первая тройка ходов каждого дебюта фиксирована, дальше играют движки; ограничение — 5000 узлов на ход, без часов. Результат 0.3.0: +5 =1 −2. Имена версий, результаты, число полуходов и причина завершения записаны в тегах. Отдельно доступна [победа 0.3.0 чёрными в партии 4](games/zenith-0.3.0-win-as-black.pgn).

Экспорт повторяется из лога стенда:

```powershell
cargo run --release --example export_pgn -- target\match-see-final.txt games\zenith-0.3.0-vs-0.2.0.pgn "Zenith 0.3.0" "Zenith 0.2.0 pre-SEE" 2026.10.24
```

Экспортёр проверяет легальность ходов, количество полуходов и причину результата перед записью PGN. Тесты SAN охватывают неоднозначные ходы, рокировку, en passant, превращение, шах и мат. Оценка силы по этим партиям относится к указанному малому лимиту поиска; рейтинг движка ещё не измерен.

Стенд `match` принимает пути к движкам, число пар, бюджет на ход, необязательный режим `nodes`/`movetime`, путь к книге и смещение. По умолчанию используются 128 позиций; повторение начинается после 128 пар. Каждое начало разыгрывается со сменой цветов. Для прежнего набора из восьми начал есть `data/openings-legacy.txt`. Флаг `--a-no-enhancements` отключает новый пакет только у движка A. Проверяются мат, пат, повторения, правило 50 ходов и недостаточный материал. После 300 дополнительных полуходов партия учитывается как ничья с причиной `ply_limit`; таймаут или нелегальный ответ завершает запуск ошибкой. Полные последовательности ходов выводятся в stdout. Это стенд для коротких проверок, без общих турнирных часов и статистической оценки рейтинга.

В рабочем `target/baselines/` сохранена исходная сборка 0.1.0 для локального сравнения; это игнорируемый Git файл, после чистого клонирования его нужно собрать отдельно. Первый короткий матч 0.2.0 против 0.1.0 при 5000 узлов на ход закончился 4:4 без ничьих, все восемь партий завершились матом. Такой объём не позволяет подтвердить изменение силы.

Идеи LMR сверены с [Chessprogramming](https://www.chessprogramming.org/Late_Move_Reductions), [поиском Reckless](https://github.com/codedeliveryservice/Reckless/blob/main/src/search.rs) и [поиском Viridithas](https://github.com/cosmobobak/viridithas/blob/master/src/search.rs). Реализация и консервативные условия Zenith написаны для собственного ядра; настройки этих движков не переносились.

Подробный [разбор архитектуры Reckless и план внедрения](docs/reckless-study.md) привязан к конкретному commit и сопровождается [картой всех файлов](docs/reckless-files.md).
