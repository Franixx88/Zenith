# Игровой поиск с NNUE — Zenith 0.13.0

NNUE v1 подключена к реальному UCI-поиску. Поддерживается существующий экспорт
`768 → 256×2 → 1`, CReLU, два i16-аккумулятора, автоматический AVX2 либо scalar.
Формат и архитектура не менялись: результат нынешнего тренера совместим с
движком. Обучение в этом изменении не запускалось; сильной обученной сети
пока нет. Без файла оценки движок использует прежнюю классику.

## Подключение после обучения

Пример UCI-команд для будущего экспорта (указанный путь — пример):

```text
uci
setoption name EvalFile value D:\Zenith\runs\v1\best.znnue
setoption name Use NNUE value true
isready
position startpos
go depth 10
```

`EvalFile` — string, default `<empty>`. Успешная загрузка автоматически выбирает
NNUE, если `Use NNUE=true` (default). Диагностика сообщает `evaluation NNUE v1`,
выбранный backend и путь. Без модели либо с `Use NNUE=false` выводится
`evaluation classical`. Пробелы внутри путей сохраняются, в том числе двойные;
кавычки вокруг UCI-значения не нужны. Относительный путь считается от рабочей
папки процесса.

Для сравнения с классикой можно отключить `Use NNUE`, сохранив загруженные
веса. Повторное включение не перечитывает файл. `EvalFile value <empty>` или
пустое значение выгружает модель. `Hash`, `Clear Hash`, `Threads`, MultiPV и
`ucinewgame` сохраняют выбор оценки и загруженную сеть. Смена Hash не требует
существования исходного файла: проверенная модель уже находится в памяти.

Загрузка ограничена размером формата и проверяет версию, размеры, checksum,
reserved fields и численные границы весов. Модель сначала полностью читается
и проверяется, затем поиск останавливается и выбор оценки меняется. При ошибке
возвращается `info string error: NNUE ...`; прежние веса и работающий поиск
сохраняются. Чужие `.nnue` Stockfish/Reckless не поддерживаются этим форматом.

Изменение активной модели очищает TT, raw eval cache, correction history,
истории ходов и сохранённых SMP-помощников. Старые оценки не могут попасть в
поиск с новыми весами. `Use NNUE=false/true` тоже изолирует классическую и
нейросетевую оценки. Сам `Network` неизменяемый и разделяется через `Arc`.

В этом этапе меняется ядро/UCI. Интерфейс локальной доски не расширялся;
его текущая сессия продолжает работать с классической оценкой. Экспорт можно
подключить в UCI-совместимом GUI указанными опциями.

## Состояние в дереве

`src/search/evaluation.rs` хранит отдельный стек для каждого поискового
потока. На входе main/qsearch сохраняется позиция соответствующего ply.
Аккумулятор этого уровня материализуется только при запросе сырой оценки:
копируется ближайший готовый предок и последовательно применяются дельты
пропущенных позиций. Отсечение по TT и терминальная проверка могут обойтись
без обновления сети. Выделения памяти происходят один раз при создании стека,
не на каждом узле. В классическом режиме стека нет.

Разности битбордов обрабатывают взятия, EP, оба направления рокировки и все
превращения. Null move меняет только позицию/порядок перспектив выхода.
Родительские суммы не изменяются при просмотре детей: возврат, отмена и
PVS re-search не требуют обратных арифметических обновлений. Новый братний
узел инвалидирует только своё состояние. Проверка исключённого хода на том
же ply может использовать готовый аккумулятор той же позиции.

Основная статическая оценка, qsearch stand-pat, NMP, малые отсечения и обучение
correction history используют выбранный evaluator. Raw cache хранит только
его сырое значение; актуальная correction добавляется при чтении. Обучение
correction сравнивает результат поиска именно с NNUE, когда она активна.
Маты, пат, повторения, недостаточный материал, правило 50 ходов и Syzygy
остаются обязанностью поиска и имеют приоритет над выходом сети.

В конце UCI-поиска добавлены диагностические счётчики:

- `nnue_refreshes`: полные построения аккумулятора;
- `nnue_updates`: материализованные переходы между позициями, включая null;
- `nnue_evaluations`: вычисления NNUE без попаданий в raw eval cache.

При обычном активном поиске одного потока нужен один refresh корня; остальные
позиции используют дельты. В SMP счётчики суммируются по потокам. Наличие
этих счётчиков позволяет проверить, что сеть действительно используется.

## Проверка корректности

Тестовые веса синтетические и не загружаются в пользовательскую сессию.
В unit-тестах каждая материализованная оценка дополнительно сравнивает все
512 i16-сумм и сырой выход с независимым полным построением на текущей Board.
Признаки тестовой модели зависят от клеток: проверка не ограничивается
материалом и обнаруживает устаревшие суммы после тихого хода.

Отдельный тестовый режим полностью пересчитывает сеть при каждом запросе.
Его поиск сравнивается с инкрементальным по оценке, лучшему ходу, всей PV,
глубине, числу узлов и MultiPV. Проверяются main/qsearch, пропущенные родители,
братние узлы, оба цвета, рокировки, EP, превращения, null move, отмена,
исключение хода, смена модели и восемь потоков. Scalar и выбранный SIMD backend
сравниваются также на уровне целого поискового дерева.

Процессные UCI-тесты используют сеть с одним понятным позиционным признаком:
на depth 1 только `e2e4` получает бонус и становится лучшим ходом. Далее
проверяются сохранение весов при смене Hash/newgame после удаления файла,
повреждённый/отсутствующий файл, переключение оценки, SMP+MultiPV, остановка
и общий лимит узлов. Неверный файл во время `go infinite` не завершает поиск.

Команды основных проверок:

```powershell
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo test --test syzygy --test syzygy_full -- --ignored
cargo test --release --lib search::nnue_tests
cargo test --test uci nnue_
```

Игровой прирост оценивается после обучения настоящей сети и парных матчей.
Результат на тестовых весах не является измерением силы.

## Результаты этого изменения

Прошли **148 обычных Rust-тестов**, **6 тестов реальных Syzygy** и
**14 Python-тестов** доски с release-кандидатом. Шесть новых тестов поискового
стека дополнительно прошли в release, включая сравнение инкрементального
и полного пересчёта на пяти стандартных позициях. Это повторная проверка
части из 148 тестов, а не ещё шесть уникальных тестов. `fmt`, Clippy с
`-D warnings` и locked-проверка binpack-адаптера проходят. Глубокий ignored
perft не повторялся; обычные правила/perft входят в общий набор.

Сеть, экспортированная независимым Node-инструментом, дополнительно загружена
в настоящий release UCI-процесс. На 16 нетерминальных FEN совпали нейросетевые
корневые оценки с независимым dense reference; проверен именно fallback
нулевой глубины при лимите в один узел. Затем MultiPV=3 завершил depth 3
на одном и восьми потоках с легальными PV. На одном потоке: 1 полный refresh,
597 инкрементальных обновлений и 637 вычислений выхода; на восьми — 8 refresh.
Реальные Syzygy с загруженной NNUE и восьмью потоками дали три отдельные
выигрывающие линии с оценками +29000 и без ошибок таблиц/помощников.
Сырые результаты, FEN, оценки, счётчики и хеши:
[`games/zenith-0.13-nnue-search.json`](../games/zenith-0.13-nnue-search.json).

Без `EvalFile` поведение совпало с 0.12.1 во всех семи конфигурациях бенча:
depth 6, 7, 8, classic, без SEE ordering, с advanced history и depth 4 без
pruning/LMR/enhancements/modern. Сравнивались все строки, кроме версии,
времени и NPS. В `bench 8` обе сборки просмотрели **502651 узел** с теми же
оценками, ходами и поисковыми счётчиками.

На Ryzen 5 2400G после прогрева выполнено по 9 чередующихся замеров depth 8
с приостановленным непрерывным анализом. Медиана 0.12.1 / 0.13.0:
**0.943322 / 0.949685 s**, около **+0.7% времени**; разброс отдельных измерений
существенно больше. Прирост скорости этим изменением не заявляется. Полные
времена и конфигурации:
[`games/zenith-0.13-classical-bench.json`](../games/zenith-0.13-classical-bench.json).

Установленный `target/release/zenith.exe` совпадает с проверенным кандидатом,
SHA-256 `cbcd7f5f797005d39e523178ae5d387d26106311778e542dcaf951cb910ba6d4`.
Локальный сервер подтвердил версию 0.13.0, сохранённую позицию и настройки
Threads=8, Hash=512 MiB, MultiPV=5. Непрерывный анализ восстановлен.
Предыдущая сборка сохранена в `target/baselines/zenith-0.12.1.exe`.
