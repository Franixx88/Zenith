# Полный набор до 5 фигур и 8 потоков — 0.10.1

Скачаны **290 таблиц**: все стандартные трёх-, четырёх- и пятифигурные
окончания, WDL и DTZ. Каталог `D:\Zenith\syzygy\3-4-5` занимает
**983 957 920 байт** самих таблиц: 938.4 MiB (0.984 GB), плюс небольшой
манифест проверки. Это полный набор указанной размерности, включая зависимые
материалы после взятий и превращений. Короли входят в число фигур.

Источники: [WDL](https://tablebase.lichess.ovh/tables/standard/3-4-5-wdl/),
[DTZ](https://tablebase.lichess.ovh/tables/standard/3-4-5-dtz/),
[опубликованные SHA-256](https://tablebase.lichess.ovh/tables/standard/sha256).
Все 290 файлов сверены с этими SHA-256. Размеры и хеши зафиксированы в
`tools/syzygy-3-4-5-manifest.json`; результат проверки находится в
`syzygy/3-4-5/verified.json`. Данные исключены из Git и находятся вне `target`,
поэтому `cargo clean` их не удаляет.

Повторяемая загрузка (Node.js 20+, npm-пакеты не нужны):

```powershell
node tools/download_syzygy.mjs
```

Можно передать другой каталог первым аргументом. Загрузчик ведёт четыре
сетевых соединения, пишет потоками в `.part`, продолжает частичные файлы через
HTTP Range, повторяет временные ошибки и переименовывает файл только после
совпадения длины и SHA-256. Повторный запуск проверяет и пропускает уже готовые
файлы. До загрузки проверяется свободное место с резервом 5 GiB.

Полный шестифигурный набор WDL+DTZ по текущему индексу источника требует ещё
160 225 616 032 байта (149.2 GiB). На D: перед загрузкой было свободно
131.0 GiB; поэтому шестифигурный набор сейчас не скачивался.

## Запуск

Пересобранный `target/release/zenith.exe` использует **8 поисковых потоков UCI**
по умолчанию. Поток приёма UCI-команд работает дополнительно. `Hash` остаётся
общим для поисковой группы, а не умножается на 8. GUI может переопределять
значения при подключении движка; тогда в настройках GUI тоже нужно указать 8.

Движок ищет `syzygy/3-4-5/verified.json` возле исполняемого файла и на двух
родительских уровнях. Для текущего расположения `target/release/zenith.exe`
это автоматически находит `D:\Zenith\syzygy\3-4-5`, независимо от рабочей
папки GUI. В UCI `SyzygyPath` показывает найденный каталог как значение
по умолчанию. Если набора рядом нет, таблицы остаются отключёнными.

Явная настройка при переносе в другой каталог:

```text
setoption name Threads value 8
setoption name SyzygyPath value D:\Zenith\syzygy\3-4-5
isready
```

Переменная `ZENITH_SYZYGY_PATH` переопределяет автоматический поиск при запуске;
`<empty>` явно отключает его. Команда `setoption` позволяет менять путь во время
работы. Маркер загрузки не заменяет повторную проверку файлов: SHA-256 считаются
загрузчиком, содержимое таблиц при поиске проверяет библиотека Syzygy.

Библиотечный `Search::new` и обычный CLI `bench` сохраняют однопоточный режим
для воспроизводимых сравнений. Для сравнения 1/4/8 потоков:

```powershell
cargo run --release --example smp_bench -- 1000 1,4,8
```

Проверки полного набора, включая выигрыш, ничью и проигрыш, слона с конём,
двух слонов, пешки и ладейное окончание, на 8 потоках:

```powershell
cargo test --release --test syzygy_full -- --ignored
```

Эталонные исходы пяти позиций независимо сверены с Lichess Tablebase API.
Алгоритмы, ограничения истории повторений и правила 50 ходов описаны в
[отчёте 0.10.0](smp-syzygy-0.10.md).

## Проверка 0.10.1

122 обычных release-теста, все 5 проверок Syzygy (малый и полный наборы) и
отдельный глубокий perft прошли: всего **128 проверок**. Clippy с `-D warnings`
и форматирование чистые. Отдельный процессный прогон, запущенный из `D:\`,
подтвердил автоподключение каталога, 8 потоков по умолчанию, табличный ответ
в пятифигурном окончании, активных помощников и общий лимит ровно 10000 узлов.
Транскрипт: `target/uci-local-syzygy-0.10.1.txt`.

Медиана aggregate NPS трёх серий по пяти позициям, 1 секунда на позицию:
1 поток — **636 783**, 4 — **1 857 268**, 8 — **3 416 326**. В каждой серии
порядок числа потоков переставлялся, параллельной компиляции/загрузки не было.
Все PV легальны, ошибок помощников нет. Сырые 45 замеров:
`games/zenith-0.10.1-smp-bench.csv`. По отношению к 1 потоку это примерно
5.36× суммарной работы на 8 потоках; это не равно ускорению решения позиции
или измеренному приросту Elo. Таблицы в этом библиотечном бенче отключены.
