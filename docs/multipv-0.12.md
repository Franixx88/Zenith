# Zenith 0.12.0 — MultiPV в движке и доске

Добавлена UCI-опция `MultiPV`, default=1, диапазон 1..32. При значении 3 движок
публикует три разных корневых продолжения с оценками и PV. Это поисковая
функция для анализа, не прибавка Elo сама по себе. Игровая оценка остаётся
классической; обученная игровая NNUE ещё не подключена.

## Поиск

На каждой глубине выполняются последовательные PVS-поиски в одном Context:
найденный лучший корневой ход исключается перед поиском следующей линии.
История, TT, deadline, счётчики и бюджет узлов общие. У каждого поиска есть
собственное aspiration window с расширением до полного окна при fail-low/high.
После завершения всего набора он сортируется по оценке за сторону хода.
При прерывании незавершённый набор не подменяет предыдущую завершённую глубину.
Если до первой полной глубины дошло слишком мало узлов, сохраняется обычный
легальный fallback, без выдуманных оценок оставшихся вариантов.

Корневые записи TT и correction history при MultiPV не публикуются: результат
после исключения одного или нескольких ходов не оценивает всю позицию.
Потомки ищутся обычным поиском и сохраняют пригодные записи TT. При смене
MultiPV сбрасываются TT/обучаемые истории; Hash/newgame сохраняют выбранное
число линий. Ограничение `searchmoves` действует на все варианты, число линий
ограничивается количеством разрешённых легальных ходов.

Lazy SMP сохраняет все заданные потоки и общую TT. Каждый помощник работает
в том же режиме MultiPV и расходует тот же глобальный бюджет. Публикуется
целостный набор основной нити. Экспериментальное голосование SMP применяется
только при MultiPV=1: замена одной линии из набора могла бы создать дубликат
корневого хода или смешать разные глубины.

Одновариантный поиск остаётся отдельной прежней веткой, без вычисления других
вариантов и дополнительных heap-буферов для линий. По умолчанию игра и бенч
используют этот режим. Количество линий не является количеством независимых
движков или отдельными лимитами времени на каждый вариант.

## Syzygy

Для MultiPV каждый реальный дочерний узел получает собственную WDL-оценку
с фактическим halfmove clock. Мат имеет приоритет над правилом 50 ходов;
пат, недостаточный материал и достижение 100 полуходов учитываются до проб.
Неоднозначный результат округлённого DTZ приводит к обычному поиску.

Первый DTZ-выбор библиотеки используется для предпочтения при равных WDL;
остальные равные варианты упорядочиваются по расстоянию до обнуления.
Округлённый DTZ не используется как доказательство WDL. Ошибка/неполный набор
таблиц не создаёт ложный табличный результат. Как и раньше, корневой DTZ
отключён при повторившихся позициях в обратимой истории: таблицы её не знают.

## UCI и доска

```text
uci
setoption name Threads value 8
setoption name MultiPV value 3
position startpos
go infinite
```

Строки результата имеют вид `info depth D multipv 1 score ... pv ...`,
`multipv 2`, `multipv 3`. Узлы/time относятся ко всей работе, их не надо
суммировать между линиями. `bestmove` соответствует первому варианту.

В доске появился переключатель «1 линия / 2 / 3 / 5 / 8» рядом с лучшим
вариантом; полный диапазон доступен в настройках. Все оценки отображаются
за белых, порядок соответствует лучшим ходам за текущую сторону. Клик
по любому ходу любой линии переносит её префикс в дерево вариантов.
Чем больше линий, тем ниже достигнутая глубина за то же время.

Адаптер использует `engine.analysis(..., multipv=N)` — python-chess сам
управляет этой опцией. Нельзя передавать её через обычный `configure()`.
Мост собирает полный набор одной глубины до публикации; новая позиция
сбрасывает незавершённые линии, старые ревизии отбрасываются. Оценка/стрелка/
график основной позиции берутся только из линии 1. Старый UCI-движок без
MultiPV продолжает работать с одним вариантом.

## Проверки

- Полные поиски каждого корневого хода на depth=3 сопоставляются с top-3
  MultiPV без селективности: совпадают оценки каждого хода и три лучших оценки.
- Проверяются уникальность корневых ходов, сортировка, легальность всей PV,
  цельные пакеты callbacks, маты, вынужденный ход, ничьи и пустой `searchmoves`.
- Общие лимиты 0/1/100/10000 узлов проверяются при 1/8/2/1 потоках; после
  возврата к MultiPV=1 дерево совпадает с новым Search.
- Живой UCI-процесс проверяет ранги, `bestmove`, `stop/isready`, смену режимов.
- Эталон `tests/data/multipv-syzygy.tsv`: 92 корневых хода, четыре KQK-позиции
  с разными цветами и halfmove clock 0/99. Оценки независимо вычислены
  python-chess 1.11.2 по локальным таблицам.
- Python-тесты проверяют сборку одной глубины без смешивания линий и живой
  нативный MultiPV с быстрыми сменами позиции.

Сборки до замены работающего exe проверяются отдельно:

```powershell
cargo test --release --all-targets --target-dir target/multipv
cargo test --release --test syzygy --test syzygy_full --target-dir target/multipv -- --ignored
$env:ZENITH_TEST_ENGINE = "$PWD/target/multipv/release/zenith.exe"
.venv-nnue/Scripts/python.exe -m unittest discover -s analysis -p test_server.py -v
```

Алгоритм реализован для Zenith. Сверка:
[UCI](https://backscattering.de/chess/uci/),
[Principal Variation / Multiple PVs](https://www.chessprogramming.org/Principal_Variation#Multiple_PVs),
[поиск Stockfish](https://github.com/official-stockfish/Stockfish/blob/master/src/search.cpp).
Исходники чужого поиска для этой функции не копировались.

## Итоговая проверка

Прошли **137 обычных release-тестов Rust**, отдельно **6 тестов реальных
Syzygy** (включая все 92 корневых оценки эталона), **14 Python-тестов моста**,
Clippy с `-D warnings`, форматирование, JS syntax check и `--locked` проверка
binpack-reader. Глубокий perft отдельно не повторялся; обычный набор perft
и правил входит в основной прогон.

На `bench 6` при MultiPV=1 относительно контрольной 0.11.0 совпали все
**128490 узлов**, оценки, лучшие ходы и счётчики. Сырые файлы:
`target/bench-multipv-baseline.txt`, `target/bench-multipv-candidate.txt` и
`target/multipv-single-parity.json`. Отдельный прирост NPS/Elo не заявляется.

В браузере проверены переключение 1→3, показ трёх разных корневых ходов,
позиция с ходом чёрных, переход по альтернативе и пауза. Снимок:
`target/multipv-analysis.png`. Доска на порту 8765 обновлена с сохранением
партии, курсора и настроек; MultiPV по умолчанию остаётся 1.

Установленный `target/release/zenith.exe` имеет SHA-256
`d6213e52c79a3588043012ef37fbaf7d99855e63c384c7ebc2e17f8d22b3df00`.
