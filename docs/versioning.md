# Как ориентироваться в версиях

Текущий номер движка задаёт `Cargo.toml`. Он выводится в ответе на `uci`.
Git-коммит определяет точный снимок исходников, а тег `vX.Y.Z` — выпущенную
версию. У уже опубликованного тега исходники и архивы не заменяются.

История изменений находится в [CHANGELOG.md](../CHANGELOG.md).
Версия Rust закреплена в `rust-toolchain.toml`; CI использует тот же toolchain.
Первая Git-версия — `v0.13.0`; более старые номера описывают исторические
этапы разработки, отдельных снимков Git для них нет.

## Проверка текущего состояния

```powershell
git status --short --branch
git log -5 --oneline --decorate
git describe --tags --always --dirty
```

Суффикс `dirty` означает локальные изменения после коммита. Команда `uci`
сообщает номер собранного движка, но не проверяет, что exe пересобран после
редактирования исходников. Для точного соответствия используй архив релиза:
в нём есть `BUILD.json` с версией, Git-коммитом, платформой и SHA-256 exe.

## Обычная разработка

```powershell
git switch -c codex/short-description
git add src tests docs
git commit -m "Describe the engine change"
git push -u origin HEAD
```

После проверки изменения объединяются в `main`. Проверки Windows/Linux
запускаются на push и pull request. Для нового релиза обнови версию в
`Cargo.toml`, оба lock-файла и `CHANGELOG.md`; добавь заметки
`docs/releases/vX.Y.Z.md`. Публикация проходит после зелёной CI в `main`.
Workflow создаёт релиз только для ещё не опубликованного номера; существующий
релиз и тег не перезаписываются. Если номер уже выпущен, повторного релиза нет.

`target/`, `runs/`, окружения Python, датасеты, нейросетевые веса и Syzygy
исключены из Git. Они остаются на локальном диске. Маленькие исходные тестовые
данные, манифесты, отчёты и контрольные PGN хранятся в репозитории.
