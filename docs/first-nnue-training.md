# Первый контрольный прогон на CUDA

26 октября 2026: GTX 1660 Ti 6 GiB, PyTorch 2.10.0+cu126, CUDA runtime 12.6,
compute capability 7.5. Проверены реальное умножение матриц на GPU и экспорт
обученного пилота: 1000 позиций совпали в trainer, независимом NumPy reference,
Rust scalar и AVX2, включая delta/refresh/dense. Это проверка арифметики,
а не доказательство игровой силы.

## Окружение

Отдельное окружение на D: не меняет CPU-окружение для Parquet/тестов:

```powershell
target/uv-tools/uv.exe venv --python 3.12 .venv-nnue-cuda
$env:UV_CACHE_DIR = 'D:\Zenith\target\uv-cache'
target/uv-tools/uv.exe pip install --python .venv-nnue-cuda/Scripts/python.exe --torch-backend cu126 -r tools/nnue/requirements-cuda126-lock.txt
```

Полный CUDA Toolkit не нужен: runtime поставляется с wheel PyTorch.
Драйвер должен поддерживать выбранный runtime. CPU-окружение и его lockfile
сохранены отдельно. Архитектура сети прежняя: 768 → 256×2 → 1 CReLU, ZNNUE v1.

## Корпус и единицы оценок

`tools/nnue/corpora/first-50gb.json` закрепляет ревизию источника, имена,
точные размеры и опубликованные SHA-256 трёх файлов: T80 August 2022,
T60/T70/Farseer и T76. Всего **49 932 598 753 байта** — 49.93 GB / 46.50 GiB.
Источник: [официальная коллекция Stockfish](https://huggingface.co/datasets/official-stockfish/master-binpacks).
Сохраняются ODbL и атрибуция исходного корпуса. Сжатые файлы читаются напрямую;
копия всех позиций в TSV/100-байтные записи не создаётся.

Downloader требует место под недостающие данные плюс 10 GiB запаса, принимает
только точные HTTP Range-ответы, возобновляет `.part` с реально записанного байта
и публикует финальное имя только после проверки полного SHA-256.
`verified.json` обновляется после каждого проверенного файла.

Рецепт `first-50gb-training.json` использует `score_num=100`, `score_den=208`,
sigmoid scale 200 в команде тренера. Это **выбор исторической конвенции**,
а не эмпирическая калибровка всех трёх источников против современного Stockfish:

- [Lc0 rescorer](https://github.com/LeelaChessZero/lc0/blob/master/src/trainingdata/rescorer.cc)
  описывает экспорт оценки с поправкой на Stockfish PawnValueEg.
- [SF15 types.h](https://github.com/official-stockfish/Stockfish/blob/sf_15/src/types.h)
  задаёт PawnValueEg=208;
  [SF15 UCI](https://github.com/official-stockfish/Stockfish/blob/sf_15/src/uci.cpp)
  переводит внутреннюю оценку в cp умножением на 100/208.

Метки reader уже относятся к стороне хода. Знак не переворачивается повторно.
Mate/sentinel отбрасываются до масштабирования, затем применяются фильтры
шаха, тактического teacher-хода, терминальных и некорректных позиций.
Train/validation разделены по каноническим входным признакам, включая цветовые
зеркала. Это защита от точных совпадений, а не разделение по партиям.

## Конечная фоновая задача

```powershell
./.venv-nnue-cuda/Scripts/python.exe -u tools/nnue/run_first_training.py --out runs/first-50gb-next
```

Каталог задачи должен быть новым. Скрипт последовательно:

1. Проверяет настоящую CUDA-операцию и докачивает/хеширует корпус.
2. Читает по 8192 принятых validation-позиции из каждого источника отдельно,
   сохраняет статистику фильтров и масштабированные диапазоны оценок.
3. Запускает обучение с нуля: максимум 48 эпох по 8 388 608 принятых позиций
   (**402 653 184 предъявления**, не число уникальных позиций), batch 8192,
   validation 131072, AdamW, cosine LR 1e-3 → 1e-5, sigmoid scale 200.
4. После 5400 секунд обучения завершает текущую эпоху и сохраняет checkpoint.
   Одна эпоха может немного превысить мягкий бюджет; процесс дополнительно
   ограничен двумя часами. Загрузка и подготовка не входят в этот бюджет.
5. Проверяет SHA экспорта, конечность validation, улучшение относительно
   нулевого baseline, затем parity на 1000 позициях и 16 пар партий против
   классической оценки того же бинарника, Threads=1, 2s+0.05s.

Состояние и логи лежат в каталоге задачи: `status.json`, `download.log`,
`training.log`, `source-checks.json`, `parity.log`, `match/summary.json`,
`match/games.pgn`. Сеть — `network/best.znnue`; рядом provenance и checkpoints.
При ошибке `status.json` получает `stage=failed` и причину; следующая стадия
не запускается. Завершение матча само по себе не означает победу кандидата.
Небольшой матч не устанавливает абсолютное Elo и не служит основанием обещать
рост силы. Доска анализа и её оценка автоматически не переключаются.

`--max-train-seconds` у самого тренера действует на один запуск и останавливает
его после сохранения полной эпохи. Для продолжения используются прежние данные
и schedule с `--resume`; для нового рецепта — новый каталог и `--init-model`.

## Пилот на префиксе

`extract_binpack_prefix.py` делает неизменяемый sample только из завершённых
BINP-блоков растущего `.part`, с ограниченной памятью и собственным SHA.
`source.json` явно отмечает partial_source=true и отсутствие проверки полного
источника. Такой sample пригоден для совместимости/замера скорости, но не
подменяет весь 50-гигабайтный корпус и не считается репрезентативной выборкой.
Данные, окружения, логи и веса исключены из Git.

Фактически запущенная задача 26 октября: `runs/first-50gb-control-20261026`.
Каталог `runs/first-50gb-20261026` относится к первоначальному запуску,
заменённому при проверке сохранения времени/provenance; активную задачу смотрим
по `first-50gb-control-20261026/status.json`.
