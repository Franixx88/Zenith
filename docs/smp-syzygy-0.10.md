# Lazy SMP и Syzygy — 0.10.0

Это отчёт о версии 0.10.0. В 0.10.1 добавлены [полный локальный набор до 5 фигур,
автоматическое подключение и 8 потоков по умолчанию](local-syzygy.md).

## Запуск

Сборка `cargo build --release`, файл `D:\Zenith\target\release\zenith.exe`.
В GUI задать Threads и SyzygyPath либо отправить UCI-команды:

```text
uci
setoption name Threads value 4
setoption name SyzygyPath value D:\Zenith\target\syzygy-tests
isready
position fen 7k/8/8/8/8/2K5/8/R7 w - - 0 1
go movetime 1000
```

`Threads`: 1–64, по умолчанию 1. `SyzygyPath`: `<empty>` отключает таблицы;
несколько каталогов разделяются `;` на Windows и `:` на Unix. Пути с пробелами
поддерживаются. `SyzygyProbeLimit`: 0–7, по умолчанию 7, 0 отключает probing.
`SyzygyProbeDepth`: 1–120, по умолчанию 1; ограничивает внутренние WDL-пробы,
корневой DTZ проверяется независимо от глубины. Файлы `.rtbw` дают WDL,
для корневого выбора с учётом счётчика нужны также `.rtbz` и зависимые материалы.
Таблицы на 4–7 фигур отдельно не скачивались.

Проверочный набор — только KQvK, KRvK, KBvK, KNvK, KPvK, обоих типов,
25 824 байта. Он не покрывает все окончания. Подготовка и запуск проверок:

```powershell
.\tools\download_syzygy_test.ps1
cargo test --release --test syzygy -- --ignored
```

Загрузчик проверяет SHA256 по сохранённому манифесту. Другой каталог тестов
можно указать переменной `ZENITH_SYZYGY_PATH`. Обычный запуск не требует таблиц.
Для новых зависимостей нужен Rust не ниже 1.95; проверяемая сборка — 1.97.1.

## Поиск в нескольких потоках

Главный поток выдаёт ход последней завершённой итерации. Помощники ведут свои
итеративные поиски, начинают с разных глубин/порядка корневых ходов и обмениваются
результатами через одну TT. Голосования результатов пока нет. У каждого потока
свои history, correction, continuation, killers, PV и статический кэш; состояния
помощников сохраняются между ходами. При изменении настроек/новой партии они
сбрасываются. Поколение TT синхронизируется перед каждым групповым поиском.

`Hash` задаёт общий бюджет таблицы и основного статического кэша, а не бюджет
на каждый поток. У помощника дополнительно около 1.5 MiB эвристик/кэшей и стек
с резервом 16 MiB. Выделение стека не означает немедленное использование всего
резерва. Число потоков выше числа физических ядер может ухудшать результат.

В общей TT 4 записи на 128-байтный bucket. Все поля атомарны, версия bucket
отмечает начало и конец записи; читатель принимает только неизменившуюся чётную
версию. Используется SeqCst, собственный unsafe не добавлен. Конкурирующая запись
может быть пропущена, занятый bucket считается промахом. Сохраняются полные
64-битные ключ позиции и fingerprint обратимой истории, счётчик 50 ходов,
бюджет продлений, глубина, bound, оценка и ход. При Threads=1 остаётся прежняя
обычная TT без атомарных обращений.

`go nodes` — строгий общий лимит всех потоков: каждый узел резервируется атомарно.
При поиске по времени статистика собирается порциями до 64 узлов; промежуточный
`info nodes` может немного отставать, финальное число полное. Общий жёсткий
deadline отсчитывается до запуска помощников; мягкий лимит контролирует главный
поток. `stop`, EOF, `quit` и смена настроек дожидаются завершения всех потоков
до нового поиска. Ошибка запуска помощника уменьшает число активных потоков,
счётчик `helper_failures` сообщает об этом. Scoped threads и guard отменяют и
дожидаются помощников также при panic пользовательского info callback.

## Табличные результаты и границы применения

Используется `shakmaty-syzygy` 0.28.1 без mmap. Один потокобезопасный набор
таблиц разделяется всеми поисковыми потоками. Регистрация проверяет имена/размеры,
содержимое читается по требованию. Неверный каталог сохраняет прежнюю настройку;
недостающая или повреждённая таблица возвращает обычный поиск. `tbhits` считает
успешные решения позиций, `tb_errors` — ошибки проб (включая отсутствующий файл).

В корне DTZ выбирает легальный разрешённый ход. Корневой WDL и WDL выбранного
потомка проверяются с их настоящими счётчиками. При неоднозначном округлении DTZ,
если выбранный ход не входит в `searchmoves`, или если в обратимой истории уже
есть повтор, короткий путь отключается. Третье повторение, 50 ходов и
недостаточный материал проверяются прежде; мат имеет приоритет над ничейной
претензией. Один FEN не позволяет восстановить неизвестную историю партии.

Внутренние WDL-отсечения разрешены только в настоящей позиции со счётчиком 0,
на достаточной глубине, вне null-пробы/её verification. Это консервативное
ограничение: WDL после обнуления не учитывает старую обратимую историю или
произвольный ненулевой счётчик. Корневой DTZ работает также при ненулевом счётчике.
Рокировки исключают probing. Cursed win и blessed loss оцениваются как ничья
по правилу 50 ходов; win/loss получают ±29000 с поправкой на ply внутри поиска.
Этот диапазон ниже матового, поэтому табличная победа не печатается как
выдуманный `score mate`. TT нормализует расстояния обоих диапазонов.

Основа алгоритмов: [Lazy SMP](https://www.chessprogramming.org/Lazy_SMP),
[Syzygy Bases](https://www.chessprogramming.org/Syzygy_Bases),
[API Tablebase и оговорки DTZ](https://docs.rs/shakmaty-syzygy/0.28.1/shakmaty_syzygy/struct.Tablebase.html).

## Воспроизводимые проверки

```powershell
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test --release --all-targets
cargo test --release --test syzygy -- --ignored
cargo test --release --test perft -- --ignored
cargo run --release --example smp_bench -- 1000
```

Проверяются публикация TT при конкуренции, смена Threads, общий node budget,
легальность PV, матовые расстояния, ограничение корня, отмена и повторный поиск,
завершение UCI по EOF/quit, WDL/DTZ на реальных файлах, превращения, счётчик 99,
табличные mainline до мата и fallback при повреждённом файле.

Масштабирование измеряется на тех же пяти позициях, по 1 секунде на позицию,
в трёх сериях с перестановкой порядка Threads=1/2/4. Aggregate NPS измеряет
суммарную работу, а не эффективное ускорение решения позиции или прирост Elo.
Короткий парный матч служит проверкой партий, а не рейтингом.

На Ryzen 5 2400G медиана aggregate NPS по суммарному времени пяти позиций:
Threads=1 — **667 298**, Threads=2 — **1 212 531**, Threads=4 — **2 005 034**.
Отношения к одному потоку: **1.82×** и **3.00×**. Все PV проверены на легальность,
ошибок помощников нет. Исходные 45 замеров: `games/zenith-0.10-smp-bench.csv`.
По завершённой глубине на этом наборе прирост обычно 0–1 ply; он не следует
линейно из aggregate NPS. Прогоны выполнены последовательно, без компиляции
или матча одновременно с замером.

Отдельные три пары `bench 6`, Threads=1, без Syzygy, против сохранённой 0.9.0:
все пять ходов, оценок, чисел узлов, null/pruning-статистики совпали, всего
128 490 узлов. Время 0.9.0: 276644 / 291675 / 276773 мкс; 0.10.0:
265417 / 247798 / 266391 мкс. Это подтверждение сохранённого дерева и отсутствия
заметной регрессии в этих прогонах; небольшой разброс времени не доказывает
отдельного ускорения однопоточного поиска.

122 обычных release-теста, 4 проверки с реальными Syzygy и отдельный глубокий
perft прошли. Форматирование и Clippy с `-D warnings` чистые.

Парный smoke-матч этой же 0.10.0: 4 потока против 1, 100 мс на ход,
Hash 16 MiB у каждого, стандартные настройки и отключённая Syzygy, четыре
дебюта из `data/openings.txt` с offset=64 и сменой цветов. Результат стороны
Threads=4: **+4 =1 −3**, без лимитных ничьих, зависаний и нелегальных ходов.
Лог и PGN: `games/zenith-0.10-smp4-vs-smp1-100ms.{txt,pgn}`. Независимый
строгий разбор PGN и повтор UCI через chess.js подтвердили 8 партий и 1168
полуходов, результаты мата/ничейных претензий. Это слишком мало для вывода
о приросте силы или Elo.

```powershell
.\target\release\examples\match.exe .\target\release\zenith.exe .\target\release\zenith.exe 4 100 movetime data/openings.txt 64 --a-threads=4 --b-threads=1
```

Отдельный процессный UCI-прогон с настоящими таблицами и Threads=4 проверил
корневые `tbhits`, сохранение таблиц после смены Hash и ошибочного SyzygyPath,
удержание готового табличного ответа при `go infinite` до `stop`.
Транскрипт: `target/uci-syzygy-0.10.txt`.
