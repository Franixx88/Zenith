# Парные матчи и экспериментальный поиск 0.11.0

Игровая оценка остаётся классической. Сохранён контрольный бинарник 0.10.1:
`target/baselines/zenith-0.10.1.exe`, SHA-256
`f8a3468310c55d95ea3c98b9bfd7184112de2a382ca687a5dd69f47578c46807`.
Новые эвристики пока выключены по умолчанию: запуск эксперимента не означает
подтверждения прироста силы. Значения параметров по умолчанию совпадают с 0.10.1.

## Стенд

`tools/engine_test.py` запускает официальный Fastchess v1.8.2-alpha. Установка
Windows x86-64 закреплена SHA-256 архива и исполняемого файла:

```powershell
powershell -ExecutionPolicy Bypass -File tools/install_fastchess.ps1
.venv-nnue/Scripts/python.exe -m unittest discover -s tools -p test_engine_test.py -v
```

Нужен только python-chess, без PyTorch: зависимости закреплены в
`tools/requirements-engine-test.txt`. Здесь используется уже существующая
`.venv-nnue`; можно установить эти два пакета в другой Python/venv и запускать
runner им напрямую. PowerShell-скрининг использует существующую `.venv-nnue`.

Каждый дебют играется дважды со сменой цветов. Сохраняются оба бинарных хеша,
хеши книги и самого runner, seed, argv, UCI-настройки после валидации,
контроль времени, исходный лог, конфигурация Fastchess и полный SAN PGN.
Папка результата должна быть новой; старые эксперименты не перезаписываются.
Seed фиксирует выбор дебютов; SMP-планирование и поиск с часами не гарантируют
битовое повторение партий. Для сравнений важны одинаковые условия и статистика.
`Threads`, `Hash`, `Move Overhead`, отключение таблиц одинаковы для обеих сторон.
Вариантные опции задаются отдельно. `Threads × concurrency` не должен превышать
число логических процессоров. Для 8 потоков используется `concurrency=1`.
Ponder, присуждение по оценке, лимит ходов и автоматическое восстановление
упавшего движка не включаются.

Независимый валидатор python-chess проигрывает каждый ход, проверяет результат
по позиции, обе партии пары и неизменность дебюта. Полученный pentanomial
сверяется с последней статистикой Fastchess. Просрочка, потеря связи, нелегальный
ход, неожиданная неполная пара или несовпадение статистики делают эксперимент невалидным.
На обнаруженном сбое турнир останавливается; лог остаётся для диагностики.
Есть общий wall-clock лимит (по умолчанию час). Преднамеренная остановка тоже
не является результатом SPRT.

При **штатном** пересечении SPRT-границы Fastchess отменяет оставшиеся партии
в работе. Завершённые одиночные партии сохраняются и отдельно перечисляются
как `unpaired_games`; в `paired_wdl`/pentanomial и вывод о гипотезе они не
входят. Такое исключение допускается только при явном H0/H1, exit code 0,
без сбоев. Неполная пара при обычном лимите партий остаётся ошибкой.
Для диагностики можно включить `--engine-log`, полный UCI trace может быть большим.

Для SPRT используется встроенная **pentanomial normalized** модель Fastchess,
alpha=beta=0.05. `--sprt 0 5` означает гипотезы об относительном nElo; это не
измерение абсолютного рейтинга Zenith. Число пар — верхний предел. Если ни одна
граница не пересечена, результат `inconclusive`. Восемь контрольных партий или
положительный счёт не заменяют этот критерий.

128 дебютных корней разделены по **семействам**, а не соседним строкам:
F01–F16 для calibration, F17–F32 для holdout, по 64 уникальные позиции.
Набор небольшой: при большем числе пар он повторяется. Перед длительным
подтверждающим тестом нужен более широкий независимый дебютный набор;
существующий стенд не устраняет эту статистическую границу.

Пример проверки отдельной фичи:

```powershell
.venv-nnue/Scripts/python.exe tools/engine_test.py target/release/zenith.exe target/baselines/zenith-0.10.1.exe target/matches/singular-example --pairs 512 --tc 0:02+0.05 --overhead 30 --threads 1 --concurrency 4 --split calibration --candidate-option "Singular Extensions=true" --sprt 0 5
.venv-nnue/Scripts/python.exe tools/engine_test.py target/release/zenith.exe target/baselines/zenith-0.10.1.exe target/matches/voting-example --pairs 128 --tc 0:02+0.05 --overhead 30 --threads 8 --concurrency 1 --split holdout --candidate-option "SMP Voting=true" --sprt 0 5
```

Для подбора констант сначала сравнивается **одна** перемена на calibration.
Сохранённый кандидат проверяется на holdout без нового подбора. Смена параметров
и переключателей сбрасывает TT и обучаемые истории, а Hash/newgame сохраняют
конфигурацию. Доступны `RFP Margin` (120; 40..300), `Futility Margin`
(120; 40..300), `NMP Base Reduction` (3; 2..5), `LMR Divisor` (300; 150..600).
Последняя опция в сотых: 300 означает знаменатель 3.0 в логарифмической таблице
LMR. Это поверхность для воспроизводимых экспериментов, а не завершённый SPSA.

`tools/screen_search.ps1` последовательно проверяет четыре отдельных кандидата:
LMR=275, NMP=4, RFP=100, futility=100. Остальные параметры каждый раз исходные.
Скрипт сохраняет варианты и все результаты; автоматически не выбирает победителя
и не меняет движок. По умолчанию только 64 партии на вариант — это первичный
скрининг, с широким разбросом и риском выбора случайного победителя.
Для текущего эксперимента до завершения скрининга выбран критерий: один
вариант с наибольшим числом очков отправляется на holdout (128 партий,
SPRT `[0,5]`); при равенстве — первый в фиксированном списке скрипта.
Параметры не меняются по результатам holdout.

```powershell
powershell -ExecutionPolicy Bypass -File tools/screen_search.ps1 -Candidate target/release/zenith.exe -Baseline target/baselines/zenith-0.10.1.exe -Output target/matches/screen-example
```

## Поиск

Singular extensions проверяет легальный TT-ход с совпавшим полным
контекстом позиции, часов и бюджета продлений. На глубине от 6, вне корня,
шаха, null-пробы и другой верификации допускается достаточно глубокая exact/
lower запись с обычной оценкой. Альтернативы ищутся без hash-хода на глубине
`(depth-1)/2` в нулевом окне у `tt_score-2*depth`. Fail-low даёт этому ходу
один дополнительный полуход. Общий с шаховыми продлениями бюджет — два
на линию. Матовые и табличные оценки не используются как основание SE.
Пока нет double/negative extensions и multicut.

Верификация консервативна: TT scores/writes, эвристическое обучение,
LMR/NMP и отсечения выключены на время проверки. Исключение действует только
в исходной позиции; потомки имеют обычные легальные ходы. Исходные PV, prior,
static eval и флаги восстанавливаются и при исчерпании узлов/отмене. Поиск без
одного хода не публикуется как полноценный результат позиции.

SMP voting рассматривает только завершённые итерации, отстающие от основной
не больше двух уровней. Проверяется вся PV и `searchmoves`. Обычные оценки
дают ограниченные положительные голоса за корневой ход с весом глубины;
у выбранного варианта берутся вместе ход, оценка, глубина и PV. Суммарные
узлы, статистика и tbhits сохраняются для всех работников. Главная матовая/
табличная оценка остаётся приоритетной; обычный результат может заменить
полностью легальная PV помощника, заканчивающаяся объявленным выигрышным матом.
Незавершённые итерации и необоснованные матовые оценки помощников не голосуют.
`info string search complete` сообщает `singular_probes`, `singular_extensions`
и `selected_worker` (0 — основной).

Алгоритмы сверены с исходниками [Stockfish](https://github.com/official-stockfish/Stockfish),
[Reckless](https://github.com/codedeliveryservice/Reckless) и описанием
[Singular Extensions](https://www.chessprogramming.org/Singular_Extensions).
Статистика реализована внешним [Fastchess](https://github.com/Disservin/fastchess).
Чужие файлы поиска для этого изменения не копировались.

## Проверки и результаты

Контроль инфраструктуры 0.10.1 против самой себя: 8 партий, +3 =2 −3,
4 корректные пары, все позиции и результаты проверены. Малый A/A — только
проверка стенда. Контроль `bench 6` с выключенными экспериментами совпал:
128490 узлов, те же оценки, лучшие ходы и счётчики.

Первый массовый запуск при concurrency=8, 2+0.02 и overhead=5 остановлен
после просрочки контрольной 0.10.1 (120 ms overrun). Он сохранён как
`target/matches/singular-calibration`, помечен `invalid`, не используется
для решения о силе. Повтор использует concurrency=4, 2+0.05, overhead=30.
Результаты окончательных прогонов после независимой валидации:

Singular, calibration, Threads=1, concurrency=4, 2+0.05: **256 партий,
+96 =49 −111**, 128 полных пар. Pentanomial `[22,24,46,19,17]` совпал с
Fastchess; все партии завершились по правилам, ошибок/просрочек нет. SPRT
`[0,5]`, LLR **−0.27**, границы **±2.94**: **inconclusive** по лимиту партий.
Это не подтверждает прирост. Singular оставлен экспериментом, default=false.
Полный [PGN](../games/zenith-0.11-singular-vs-0.10.1.pgn), исходные артефакты
`target/matches/singular-calibration-safe/`. SHA-256 проверенного кандидата:
`c06f1e8260c35a38ec34f557e41e8db9be369cd73f7525380f2578d7c7605000`.

SMP voting, holdout, Threads=8 у обеих сторон, concurrency=1, 1+0.03:
**64 партии, +33 =14 −17**, 32 полные пары. Pentanomial `[1,6,10,6,9]`,
все партии завершились по правилам, ошибок нет. SPRT `[0,5]`, LLR **+0.26**,
границы **±2.94**: **inconclusive**. Результат обнадёживает, но заданный
критерий подтверждения не выполнен: default=false. Полный
[PGN](../games/zenith-0.11-voting8-vs-0.10.1.pgn), манифест, лог и summary
в `target/matches/voting-holdout/`.

Скрининг констант, calibration, Threads=1, concurrency=4, 1+0.03,
по 64 партии (32 пары), всё без ошибок:

- LMR Divisor=275: +22 =12 −30, 28 очков;
- NMP Base Reduction=4: +27 =13 −24, 33.5 очка;
- RFP Margin=100: +29 =10 −25, 34 очка;
- Futility Margin=100: +22 =18 −24, 31 очко.

По заранее выбранному критерию на holdout отправлен **RFP Margin=100**,
все остальные настройки исходные. Это выбор кандидата для проверки, а не
доказательство улучшения. Исходные партии, манифесты и результаты каждого
варианта находятся в `target/matches/parameter-screen/`.

RFP=100 на holdout, те же 1+0.03, Threads=1, concurrency=4:
**128 партий, +41 =36 −51**, pentanomial `[9,15,23,11,6]`, всё корректно.
SPRT `[0,5]` не завершён по лимиту партий. Положительный результат calibration
не подтвердился на holdout; **RFP Margin остаётся 120**. Другие параметры
тоже сохраняют исходные значения. Полный
[PGN](../games/zenith-0.11-rfp100-holdout-vs-0.10.1.pgn).

Итого **704 корректные экспериментальные партии**: 256 singular, 64 voting,
256 скрининга и 128 holdout параметра. Ни одна из проверяемых новых эвристик
не получила подтверждения заданным SPRT, поэтому итоговая конфигурация
консервативно сохраняет прежнее игровое поведение.

Отдельный тест **механизма** ранней остановки: 0.10.1 против самой себя,
2000 узлов на ход, искусственные отрицательные гипотезы `[-200,-100]`.
Fastchess принял H1 через 18 партий (9 пар), до верхнего лимита 128;
PGN/pentanomial проверены, итоговое завершение штатное. Этот H1 не является
приростом двигателя: обе стороны идентичны, проверялась проводка стенда.
Артефакты в `target/matches/aa-sprt-stop/`, включая полный UCI trace.

Дополнительная проверка живого UCI-процесса с обеими эвристиками на 8 потоках:
12 позиций по 50000 общих узлов, 12 легальных PV; в 9 случаях выбран
результат помощника, ни одного `helper_failure`. Лог:
`target/experimental-uci-check.json`.

Сводный [машиночитаемый отчёт](../games/zenith-0.11-search-tests.json) сохраняет
манифесты и результаты всех семи экспериментов вне игнорируемого `target`.
PGN всех четырёх вариантов скрининга сохранены рядом как
`games/zenith-0.11-screen-*.pgn`. Невалидный первый прогон и служебные A/A
не входят в 704 экспериментальные партии.

Окончательная проверка: **132 обычных Rust-теста**, **5 тестов реальных Syzygy**
(полный 3–5-фигурный набор проверен на восьми потоках с SE/voting),
**7 Python-тестов стенда** — всё проходит. `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`, `cargo check --locked --manifest-path tools/binpack/Cargo.toml`
и release-сборка проходят. Отдельный глубокий perft в этом изменении не повторялся;
обычные perft/rules тесты входят в 132.

Сравнение `bench 6` на свободном процессоре: после прогрева по 9 измерений
в чередующемся порядке. Медианы 0.10.1 / финальной 0.11.0 — **0.324581 /
0.326281 s**, разница около **+0.5% времени**, при заметном разбросе отдельных
измерений. Прирост скорости не заявляется. Все 128490 узлов, оценки, лучшие
ходы и счётчики совпали во всех запусках, включая сохранённый кандидат.
Сырые измерения: `target/bench-0.11-comparison.json`.
