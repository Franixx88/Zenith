# Zenith 0.9.0 — генерация, селективность и AVX2

## Исправления горячего пути

Поиск больше не получает заранее полностью легализованный `Vec<Move>` на каждом
узле. `MovePicker` работает по стадиям: проверенный TT-ход, хорошие тактические
ходы, тихие, плохие тактические. Quiet generation выполняется после исчерпания
хороших captures/promotions; при отсечении на hash-ходе другие стадии не
генерируются и не сортируются. SEE тактических ходов остаётся пакетной на стадии
тактики; это ещё можно оптимизировать отдельно.

Генератор выдаёт псевдолегальные ходы в фиксированный `MoveList`. Выбранный ход
проходит проверку короля и сразу возвращает дочернюю Board, используемую поиском.
Нет второй копии Board для того же выбранного хода. TT-ход проходит отдельную
проверку геометрии без генерации полного списка (редкая рокировка использует
quiet generator для проверки пути). Взятие короля и некорректные promotions
отвергаются. EP и раскрытие линии на короля проверяются на дочерней позиции.

MovePicker использует один фиксированный scored buffer. Списки уже проверенных
quiets/captures тоже фиксированные. Для обоих используется безопасный API
`arrayvec 0.7.8`: хранилище inline, без heap, инициализирован только реально
заполненный префикс. Начальный вариант с очисткой всей вместимости показал
регрессию и заменён после замеров. PV хранится в массивах по ply, выделенных
один раз на поиск; root/PV для UCI по-прежнему выдаются в Vec вне горячего пути.
История пути заранее резервирует ещё MAX_PLY+1 элементов. Публичные
`Board::legal_moves()`/`legal_tactical_moves()` сохраняют Vec-интерфейс для UCI,
perft и внешних инструментов; внутри основного поиска эти API не вызываются,
кроме начального списка корня.

Буферы имеют вместимость 512: при <=16 фигурах на сторону даже грубая верхняя
граница 16×27 queen destinations ниже этого числа; пешка с четырьмя promotions
на три направления даёт максимум 12 ходов. Проверка вместимости остаётся в
release. Стек UCI worker резервирует 16 MiB виртуального адресного пространства;
это один поисковый поток, не Lazy SMP. Ошибка запуска worker восстанавливает
состояние движка.

Терминальные позиции определяются до stand-pat/RFP/NMP: наличие legal TT move
служит доказательством существования ответа, иначе генератор останавливается
после первого легального хода. Для шаховых продлений считаются максимум четыре
легальных ответа. В 0.9 снято прежнее продление единственного тихого хода:
предварительное доказательство уникальности конфликтовало с ленивым hash cutoff.
Шах с <=3 ответами по-прежнему продлевается, общий бюджет — два полухода.

## Новый поисковый пакет

`Modern Search=true` и `Null Move Pruning=true` теперь включены по умолчанию
после положительных коротких контрольных матчей. Это предварительный выбор
конфигурации, не статистическое доказательство прироста Elo. Настройки
независимые: `Null Move Pruning=false` действительно отключает NMP даже при
включённом Modern Search. Смена конфигурации очищает TT, eval cache и обучение.
Обе настройки сохраняются через Hash resize и ucinewgame.

В Modern Search добавлены:

- **LMP:** пропуск поздних quiet moves при depth<=4, порог
  `2 + depth² + 2*improving`, история <=0.
- **Quiet futility:** depth<=3, static +100+120*depth <=alpha, history<2000.
- **History pruning:** depth<=2, history <−1200*depth.
- **Quiet SEE pruning:** depth<=4, history<1000, SEE <−30*depth².
- **LMR:** логарифмическая формула без прежнего потолка 1–3, до depth−2.
  Разрешены обычные пешечные ходы и достаточно поздние PV moves, у последних
  reduction на один меньше. Checks, evasions, promotions, captures, killers,
  countermoves, хорошая история, продвинутые и проходные пешки защищены.
  Улучшение alpha после сокращения всегда перепроверяется на полной глубине.
- **IIR:** на depth>=5 без legal hash move, вне корня/шаха/искусственной
  null-ветки глубина уменьшается на один. TT записывает именно уменьшенную
  глубину; регрессия проверяет, что просмотр depth4 не публикуется как depth5.
- **Pawn correction history:** 2×16384 i16 значений, 64 KiB вне Hash. Поправка
  ограничена ±128 cp. Сырой eval cache хранит только классическую оценку;
  текущая поправка прибавляется при чтении, не кешируется внутри raw score.
  Обновление — EMA по разнице search−raw, с учётом типа границы, только после
  тихого лучшего хода, вне шаха, матовой области, искусственных веток,
  ограниченного searchmoves корня, маломатериальных позиций и близости 50 ходов.

Новые quiet prunings работают только после уже просмотренного легального хода,
вне корня, PV, шаха и матовых окон, с уже найденной нематовой оценкой,
при >8 фигурах и halfmove<80. Не отсекаются шахующие ходы, promotions/captures,
killers/countermoves и опасные пешечные продвижения. Шах и пат не заменяются
ложной оценкой из-за отсутствия просмотренных ответов.

В modern NMP null-проба сохраняет LMR/RFP/quiet prunings, но не читает TT scores,
не записывает их и не обучает историю/correction. Вложенный NMP запрещён.
Репетиции не пересекают искусственную границу. После fail-high на depth<10
принимается отсечение; от 10 выполняется проверка реальными ходами с прежним
полным подавлением селективности. Guard по пешкам и двум non-pawn фигурам с
материалом >=950 сохранён; пешечные и одиночные ладейные эндшпили исключены.
Статический запас снижен с beta+50 до beta. При Modern Search=false доступен
прежний вариант NMP с обязательной верификацией. Это эвристика, не решатель
цугцванга во всех возможных позициях.

Singular extensions пока не добавлены. Lazy SMP/Threads, Syzygy, ponderhit,
Chess960 и PEXT также не реализованы в этом пакете. AVX-512 backend отсутствует;
он не доступен для выполнения на проверенном Ryzen 5 2400G.

## NNUE: i16 и AVX2

Два аккумулятора теперь занимают **1024 байта сумм** вместо 2048, плюс Board и
ссылка на сеть. Формат весов v1 не изменился. При установленных границах параметров
и 32 фигурах |sum|<=20480, поэтому i16 достаточен. Удаления выполняются до
добавлений, промежуточные позиции остаются под той же границей.

AVX2 обновляет 16 i16 lanes за инструкцию. Выход использует CReLU и signed
`madd_epi16`, i32 суммы и окончательную i64 арифметику. Независимый i64 reference
сохранён. Насыщения аккумуляторов нет: оно разрушило бы точность отката.

Выбор backend автоматический через CPU/OS feature detection; scalar всегда
доступен. `Network::with_backend(Backend::Scalar/Avx2)` позволяет независимое
сравнение; unsupported forced backend возвращает ошибку. Каждый unsafe вызов
защищён проверкой AVX2 и размерами массивов. Loads/stores unaligned: требования
к 32-байтному выравниванию пользовательских буферов нет.

Глобальный запрет `forbid(unsafe_code)` заменён на `deny(unsafe_code)`;
единственное локальное исключение — private `src/nnue/kernels.rs`.
`unsafe_op_in_unsafe_fn=deny` действует везде. Оптимизированного PEXT генератора
это изменение само по себе не добавляет.

```powershell
cargo run --release -- bench 6
cargo run --release -- bench 6 --classic
# Современный поиск без NMP: порядок ключей здесь намеренный.
cargo run --release -- bench 6 --modern --no-nmp
cargo run --release --example nnue -- bench target/nnue-stage1-synthetic.znnue 1000000 --scalar
cargo run --release --example nnue -- bench target/nnue-stage1-synthetic.znnue 1000000 --avx2
```

В UCI контрольный режим: `setoption name Modern Search value false` и
`setoption name Null Move Pruning value false`. В match runner есть
`--a-classic`/`--b-classic`, а также `--a-modern`/`--b-modern` для явного выбора
обеих настроек. Флаги одного движка взаимно исключаются. У старой 0.8.0 нет
Modern Search: для неё оставлять исходные настройки без этого флага.

## Проверки и предварительные матчи

Три последовательных `bench 6` на том же Ryzen 5 2400G, без параллельных
матчей и компиляции (время суммарно по пяти позициям):

- 0.8.0: 0.760315 / 0.800598 / 0.787424 s, медиана **0.787424 s**, 364220 узлов.
- 0.9.0 `--classic`: 0.549399 / 0.542374 / 0.551977 s, медиана **0.549399 s**,
  364409 узлов. Около 1.43 раза быстрее по времени; медиана NPS около 663 тыс.
- 0.9.0 default: 0.266595 / 0.267103 / 0.259923 s, медиана **0.266595 s**,
  128490 узлов. Около 2.95 раза быстрее 0.8.0 до запрошенной глубины; медиана
  NPS около 482 тыс. Пропущенные/сокращённые ветви меняют дерево и score.

Логи: `target/bench-0.9-final-{old,core,full}-{1,2,3}.txt`. Перед заменой полностью
инициализированных буферов на ArrayVec контрольное ядро было примерно на 12%
медленнее 0.8.0. Этот вариант не оставлен финальным. После замены совпали все
пять scores, bestmoves, nodes и поисковые счётчики современного пакета; финальные
буферы не меняют его алгоритмическую выборку.

На миллион позиций NNUE, три последовательные серии без параллельной нагрузки:
scalar delta+head 585.948 / 567.231 / 575.937 ms; AVX2
188.799 / 192.925 / 190.189 ms. Медианы **0.575937 / 0.190189 мкс**, отношение
**3.03**. Full refresh+head ускорился с медианы 1.036989 до 0.751074 мкс, то есть
около 1.38 раза; трёхкратный выигрыш относится именно к инкрементальному пути.
Checksum во всех сериях −15081351800. Это синтетическая сеть на ограниченном
наборе, не скорость игрового поиска с будущими обученными весами. Логи:
`target/nnue-0.9-{scalar,avx2}-{1,2,3}.txt`.

113 обычных release-тестов, Clippy и отдельный глубокий perft прошли, включая
повторение после смены defaults и перехода на ArrayVec. Регрессии
старого поиска явно включают classic configuration; интеграционные tactics и
modern tests упражняют новые defaults. Отдельно проверяются совпадения scalar /
AVX2 / dense reference, экстремальные параметры, каждый lane, EP/promotion/undo,
геометрия TT-хода по всем from/to/promotion на эталонных досках, очистка correction
и сохранение raw cache, отмена NMP и глубина TT после IIR.

Короткие парные матчи на фиксированных восьмиполуходовых началах:

- Новое ядро с выключенным пакетом против 0.8.0: **+6 =5 −5**, 16 партий,
  10 000 узлов на ход, без присуждений по длине.
- Modern+NMP против нового ядра без пакета: **+17 =9 −6**, 32 партии,
  10 000 узлов; одна ничья по лимиту длины.
- То же при 50 ms на каждый ход: **+10 =0 −6**, 16 партий, другие восемь начал,
  без присуждений по длине. Это fixed movetime, не турнирные часы.

Эти первые три матча проверяли тот же поисковый алгоритм до замены полностью
инициализированных буферов на ArrayVec. Для окончательной сборки повторно
проверены defaults, полный набор тестов и проведены ещё два матча:

- **+12 =0 −4 против 0.8.0**, 16 партий по 10 000 узлов, восемь новых начал
  (offset 24), без присуждений по длине.
- **+10 =2 −4 против 0.9.0 classic**, 16 партий по 50 ms, offset 16, без
  присуждений по длине. Обе стороны используют окончательные буферы ArrayVec.

Суммарно 96 партий и 12 552 полухода независимо проверены через strict PGN и
повтор UCI в chess.js 1.4.0. Нет нелегальных ходов/зависаний. Начала последнего
матча повторяют первоначальный 50ms опыт; это не независимая рейтинговая выборка.
Окончательные партии: [против 0.8.0](../games/zenith-0.9.0-vs-0.8.0-10k.pgn),
[против classic](../games/zenith-0.9.0-vs-classic-50ms.pgn). Исходные логи рядом
с расширением `.uci`. SHA-256 повторно сгенерированного дебютного набора совпал.

Часть дебютов совпадает между опытами. Объём мал, выбранные параметры не прошли
SPRT, фиксированный Elo и гарантированное усиление не заявляются. Нейросеть
ещё не обучена и в игровом поиске не используется: AVX2 измеряется на отдельном
синтетическом стенде. PGN и исходные UCI логи сохранены в games/.
