# NNUE v3: зеркальные банки и многослойная оценка

Экспериментальная архитектура: **16 × 768 → 512**, два аккумулятора i16,
парное произведение активаций и **8 выходных голов 512 → 16 → 32 → 1**.
Файл занимает **12 725 408 байт**, около 12.14 MiB. Движок продолжает читать
v1/v2; рекомендованная игровая сеть определяется результатами матчей.

## Координаты и аккумуляторы

Для каждой перспективы сначала переворачиваются ранги чёрных (`square ^ 56`).
Если свой король находится на e–h, все признаки зеркалятся по вертикальной
оси доски: a↔h, b↔g, c↔f, d↔e (`square ^ 7`). В канонической половине
доски четыре файла и четыре пары рангов дают 16 банков:

```text
canonical_king = relative_king ^ (mirror ? 7 : 0)
bank = (canonical_king / 16) * 4 + canonical_king % 8
context = bank + 16 * mirror
```

Контекст включает флаг отражения. Переход короля d1→e1 требует пересчёта
своей перспективы, хотя канонический номер банка остаётся тем же. Вторая
перспектива обновляется дельтами. Рокировка, EP, превращение, null move,
откат, смена FEN и пропущенные родительские оценки поддерживаются.

V1/v2 используют прежние кадры из 256 нейронов; широкие кадры создаются
только для v3. Модель общая и неизменяемая, аккумуляторы отдельные для каждого
потока SMP. `nnue_bucket_refreshes` включает смены банков и отражения.

## Целочисленные слои

```text
a[p] = clamp(ft_bias + sum(ft_weights[bank,feature]), 0, 255)
pair[p,i] = trunc(a[p,i] * a[p,i+256] / 255), i=0..255
x = concat(pair[side_to_move], pair[opponent])
head = min(7, max(piece_count - 2, 0) / 4)
h1 = clamp(trunc((W1*x + b1) / 64), 0, 255)
h2 = clamp(trunc((W2*h1 + b2) / 64), 0, 255)
raw = Wout*h2 + bout
cp = clamp(trunc(raw * 400 / (255*64)), -28000, 28000)
```

Число фигур включает обоих королей. Вычисляется одна выбранная голова.
Парный слой выбран вместо SCReLU; он даёт взаимодействия между половинами
вектора и сокращает вход следующего слоя до 512. Это отдельная архитектура,
а не точный перенос обученной функции v1.

Обновления FT, парные произведения и скалярные произведения имеют AVX2 с
runtime-проверкой CPU и scalar fallback. Для деления парных произведений
используется точное `floor(x/255) = (x + 1 + (x >> 8)) >> 8` при x≤65025.
Все 65536 сочетаний входных значений проверяются на совпадение с делением.

Ограничения параметров: FT i16 ±512, bias ±4096; головы i16 ±127,
их bias i32 ±65536. Максимум FT-суммы — ±20480. Максимальное по модулю
промежуточное значение первой головы — 16646656, меньше 2²⁴; последующих
слоёв — ещё меньше. Максимальный выход 1101856 остаётся вне матовой зоны.
Поэтому FP32 может точно представлять целые суммы при QAT. Численные границы
проверяются при загрузке всех банков и голов.

## Формат

Little endian, magic `ZNNUE\0\0\0`, заголовок 128 байт.
С offset 8 идут восемь u32: `[3,768,512,16,255,64,400,8]`.
Offset 40: payload u64; 48: FNV-1a64 всего файла с обнулённым полем checksum;
56: flags u64=3 (отражение и парный слой).
Offset 64: четыре u32 `[16,32,128,1]` — размеры следующих слоёв, заголовок,
версия активации. Байты 80..127 должны быть нулевыми.

Payload: 512 bias FT (i16), 16×768×512 весов FT (i16, bank/feature/neuron).
Затем восемь голов: W1 (16×512 i16), b1 (16 i32), W2 (32×16 i16),
b2 (32 i32), Wout (32 i16), bout (i32). Матрицы голов output-major.
Загрузка ограничена фиксированным максимальным размером; несовпадение размера,
параметров архитектуры, checksum, reserved-полей или границ отвергается.

## Обучение

`train_nnue.py --architecture v3` включает QAT с точным округлением ties-away
и STE-градиентом. Деление и отсечение соответствуют inference движка.
Финальный cp вычисляется через `raw*5/204`, чтобы не терять точность FP32
при большом промежуточном произведении на 400. TF32 отключён.
Экспорт применяет тот же FP32 масштаб и округление, что и QAT.

Общий обучаемый FT-фактор 768×512 складывается с остаточными весами каждого
банка. При экспорте он сворачивается в 16 банков; inference дополнительных
признаков не получает. Это позволяет общей части учиться на всех положениях
короля. Запуск с v1/v2 checkpoint отвергается: отражение, парные активации
и новые слои не сохраняют прежнюю функцию. V3 обучается с нуля, поддерживает
точное продолжение checkpoint с optimizer, RNG, фактором и контрактом запуска.
Legacy-тренер сохраняет порядок операций и контракт resume v1/v2.

Локальный полный эксперимент:

```powershell
.venv-nnue-cuda/Scripts/python.exe -u tools/nnue/run_v3_training.py --out runs/layered-v3-control-20261027
```

План: 24 эпохи по 8388608 принятых позиций (до 201326592 предъявлений),
batch 8192, seed 3, AdamW LR 1e-3→1e-5, validation 131072, sigmoid scale 200.
Лимит обучения 5400 секунд, с завершением текущей эпохи. Источники — уже
проверенные T80, T60/T70/Farseer и T76, всего 49.93 GB. Скачивание и полная
распаковка не нужны. Число предъявлений не означает число уникальных позиций.

Контроллер сохраняет план, хеши, копии тренера/проверки и нативных бинарников,
статус и логи. После обучения проверяет лучший checkpoint на CPU/CUDA,
проводит parity с Rust и 128 парных партий против стабильной v1. У обеих сторон
`Context Histories=false`, Threads=1, Hash=32 MiB, 5s+0.05s, Syzygy выключены.
История обучения v1 и v3 различается: это проверка готовности кандидата,
а не изолированное доказательство преимущества размера сети.

Пилот на ограниченном T80-префиксе проверил CUDA и экспорт: batch 8192,
1048576 предъявлений за эпоху, около 49 тысяч позиций/с внутри эпохи.
Его loss не характеризует силу полной сети. Проверка на 1024 позициях:
QAT CUDA, trainer integer, NumPy, Rust scalar и AVX2 совпали точно.
Пилот не используется как стартовый checkpoint полного обучения.

## Поиск и проверки

Независимая UCI-опция **`Context Histories`** (по умолчанию false) включает:

- Quiet history по угрозам на исходном/целевом поле.
- Quiet history по пешечной структуре, стороне, типу фигуры и целевому полю.
- Correction history по непешечным фигурам каждого цвета, в дополнение
  к существующей пешечной коррекции; компоненты усредняются.

Геометрические атаки противника кешируются на каждом ply по хешу доски.
Таблицы принадлежат потоку; переключение сбрасывает TT, eval cache и workers.
Обучение подавлено в искусственных null/excluded-поисках, raw NNUE/eval cache
содержит исходную оценку без correction. Опция также доступна в bench через
`--context-history`. Её матч использует одинаковую стабильную v1 с обеих
сторон, чтобы отделить изменение поиска от новой архитектуры.

Проверки включают все банки/отражения/выходные группы, независимую арифметику,
специальные ходы, undo, null, широкие ленивые кадры, пределы чисел,
повреждённые файлы, CPU resume и SMP/MultiPV/отказ загрузки во время поиска.
Локально прошли `cargo test --locked --all-targets`: **165 тестов**, 7 отдельно
помеченных ignored (глубокий perft и реальные таблицы). `cargo fmt --check`
и Clippy с `-D warnings` чистые. Дополнительно прошли 13 Python-тестов
пайплайна/v2/v3; QAT CUDA и нативный экспорт совпали на 1024 позициях.
Журнал полного Rust-прогона: `runs/v3-validation-20261027/rust-tests.log`.

Первый короткий матч Context Histories прерван по просрочке времени во время
параллельной тяжёлой проверки; его `summary.json` имеет `valid=false`.
Он исключён из оценки силы. Повторная серия использует 64 пары, 10s+0.10s,
concurrency=1, overhead=75 ms и журнал UCI:
`runs/v3-validation-20261027/context-history-match-retry`.

Веса, checkpoints и 50 GB данных остаются локальными. По завершении необходимо
изучить PGN и неопределённость результата; автоматической замены сети в доске нет.
