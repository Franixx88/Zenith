# Первая обученная игровая сеть

Контрольный прогон `first-50gb-control-20261026` завершил подготовку корпуса,
обучение и проверку экспорта. Отключение электричества не оборвало этот прогон.
После включения отдельно проверяются полный корпус, checkpoints и игровые
результаты. Это сеть формата Zenith ZNNUE v1, не формат `.nnue` Stockfish.
Все три файла корпуса после отключения повторно прочитаны целиком:
размеры и SHA-256 совпали с закреплённым манифестом. Хеши лучшей/последней
сети и последнего checkpoint также совпали с provenance.

## Воспроизводимость

Исходный код обучения: `7a4a816088ab16c066740145b6b4370d7160493b`.
Корпус закреплён в `tools/nnue/corpora/first-50gb.json`: T80 August 2022,
T60/T70/Farseer и T76, всего 49 932 598 753 байта. Источник и атрибуция ODbL
сохраняются с моделью. Масштаб меток 100/208 и остальные допущения описаны
в [рецепте первого обучения](first-nnue-training.md).

Архитектура 768 → 256×2 → 1 CReLU, два i16-аккумулятора, AVX2/scalar.
48 эпох по 8 388 608 принятых позиций — 402 653 184 предъявления, не число
уникальных позиций и не полный проход по всем данным. Обучение на GTX 1660 Ti
заняло 2632 секунды. Лучший экспорт выбран на эпохе 45 по quantized validation
loss 0.01084087, validation 131072. Loss первой эпохи 0.01748538; baseline
нулевой оценки 0.03845332. Эти метрики не являются оценкой Elo.

SHA-256 лучшей сети:
`1c7c79756c6e8bf431c718866439f90fa9bcb8654c7eee7067768d1ffea85e7b`.
Файл занимает 394820 байт. Экспорт сверяется с provenance; parity на 1000
позициях совпала между trainer, NumPy, Rust scalar и AVX2, включая delta,
refresh и dense reference.

## Проверка силы

Первоначальный матч на calibration-дебютах: 32 партии, +24 =4 −4,
2s+0.05s, Threads=1, Hash=16 MiB, Syzygy выключена. Оба участника — один
и тот же бинарник; кандидат с `EvalFile`, baseline с `Use NNUE=false`.
Все партии независимо переиграны и проверены на легальность, без forfeits.
Это предварительный результат; отдельный holdout-матч проверяет перенос
на другие дебютные семейства при более длинном контроле.

Holdout-проверка завершена: **128 партий, +107 =15 −6**, 5s+0.05s,
Threads=1, Hash=32 MiB, concurrency=4, Syzygy выключена. Счёт 114.5/128
(89.45%). 64 пары со сменой цветов; pentanomial [0, 0, 6, 15, 43].
Ни просрочек, ни нелегальных ходов, ни иных forfeits; независимая проверка PGN
прошла для всех партий. [Контрольные партии](../games/zenith-nnue-v1-holdout-20261027.pgn).
Это относительный результат NNUE против классики на этих условиях,
не рейтинг Zenith относительно внешней рейтинговой шкалы.

Веса, полные checkpoints и датасеты остаются локально вне Git. Исходный экспорт
лежит в `runs/first-50gb-control-20261026/network/best.znnue`; полный provenance
и результаты — рядом. У уже опубликованного релиза v0.13.0 нет встроенных весов.
Неизменяемая локальная копия выбранного экспорта:
`networks/zenith-v1-1c7c79756c6e.znnue`; сведения и SHA —
[`networks/first-control.json`](../networks/first-control.json).
Архив `dist/zenith-nnue-v1-first-control-20261027.zip` содержит сеть,
provenance, исходный манифест корпуса, результаты integrity/parity и PGN.

## Использование и бенч

В UCI-совместимом GUI можно задать `EvalFile` на этот файл и включить `Use NNUE`.
Пример для локального рабочего дерева:

```text
setoption name EvalFile value D:\Zenith\networks\zenith-v1-1c7c79756c6e.znnue
setoption name Use NNUE value true
```

Поисковый бенч теперь принимает тот же файл, проверяет его до начала поиска,
выводит выбранный backend и счётчики neural refresh/update/evaluation:

```powershell
cargo run --release -- bench 6 --eval-file networks/zenith-v1-1c7c79756c6e.znnue
```

Без аргумента `--eval-file` бенч использует классику. Сравнение NPS между разными
оценками не доказывает рост силы: они дают разные оценки и разные деревья.

На собранном release-бинарнике проверены оба режима бенча на глубине 6;
нейросетевой режим выбрал AVX2 и показал ненулевые счётчики аккумуляторов.
Отдельно настоящая обученная сеть прошла UCI-проверку с Threads=8,
Hash=128 MiB, MultiPV=5 на трёх позициях: все 15 PV легальны, первые ходы
в каждой пятёрке различаются. Это проверка совместной работы SMP и NNUE,
а не оценка прироста силы от восьми потоков.
